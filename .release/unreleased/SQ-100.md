---
ref: SQ-100
title: The negative-control gate demands markers only for the tests a candidate changed itself, not the tests a merge brought in
bump: patch
plugins: [sidequest]
---

A candidate that merged another branch, such as upstream develop into a fork PR tip or main into a ticket branch, was refused with `negative_control_test_required` for every test the merge carried in, because the gate diffed the whole range from the dispatch base (GH-160). Both the `[sidequest:verify-complete]` comment gate and `submit` now attribute tests along the candidate's first-parent history: a merge on that line answers only for its conflict-resolution hunks and hand edits, where its result differs from every parent, and ordinary commits keep the diff they always had. A test the resolution changes still needs its `[sidequest:negative-control-test]` line, and a test a later commit renamed or deleted is no longer demanded under its old name.

`submit` also attributes from its validated range base when that base lies between the dispatch base and the candidate, so commits a fast-forward merge took from an integration branch that has since caught up are no longer demanded. The comment gate has no range, so a fast-forward merge there still counts the merged commits until submit. Linear history keeps the exact paths and test names it had before. The refusal and recovery text now say "this candidate added or modified".
