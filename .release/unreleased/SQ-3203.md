---
ref: SQ-3203
title: "hooks.json never routed force-exec-bypass for board remove, so an executor's forced remove wasn't denied at the hook boundary"
bump: patch
plugins:
  - sidequest
---

`LIVE_CLAIM_MUTATION_RULES` (in `force-exec-bypass.ts`) has always denied a subagent's `mcp__plugin_sidequest_board__remove {force: true}` on its own live claim, but `hooks.json`'s PreToolUse matchers only ran that hook for `board__update`, `board__dispatch`, `Agent`, `SendMessage`, `Bash|PowerShell`, and `Edit|Write|MultiEdit|NotebookEdit` — never for `board__remove`. Claude Code ran only `inline-work-nudge`, `guard-denied-tools`, and `bind-runtime-identity` for `remove`, so the rule was dead code at the hook boundary and an executor could force-remove its own ticket unblocked. The matcher now covers `mcp__plugin_sidequest_board__(update|remove)`. A new hooks.test.ts regression reads the live-claim mutation rule tool names straight out of the source and asserts each one has a PreToolUse matcher that runs `force-exec-bypass.js`, so a future rule can't be added without its route again.
