ref: SQ-55
title: Lease each crossed sibling executor to the checkout it actually runs in
bump: patch
plugins: [sidequest]
---

Follow-up to GitHub #298. WorktreeCreate attributes each new checkout to a reservation in creation order, so executors spawned in one Agent message, of the same or different executor types, could each be leased to the other's checkout, and every write was refused with "has no write lease for this linked worktree". The claim now settles this. When the checkout the executor runs in is the exact instance a sibling's unclaimed, unconfirmed reservation recorded, the two checkout bindings are exchanged under both ticket locks. The claim result then names the corrected worktree. A claimed, token-confirmed, or terminal sibling binding is never moved.
