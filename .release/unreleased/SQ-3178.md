---
ref: SQ-3178
title: "Archiving a board moves its refs/sidequest/SQ-n candidates aside, and the board no longer repoints a candidate ref another board owns (GH-378)"
bump: patch
plugins:
  - sidequest
---

A new board for the same repository, for example after the repository moved, numbers its tickets from SQ-1 again, so its candidates overwrote the archived board's `refs/sidequest/SQ-n` or could build on a stale one. `archive-board` / `archive_board` now moves every candidate ref whose commit the board's tickets recorded (submission, checkpoint, board commits, rejected submissions) to `refs/sidequest-archived/<board>/`, in one atomic `update-ref` transaction, and reports the moves as `candidateRefs`. Archiving an already archived board runs the move again, so a board archived before this fix can be cleaned up the same way. `unarchive-board` moves them back unless another board now holds the live name, and lists those as `keptArchived`. Every board write to `refs/sidequest/*` is compare-and-set against a tip the ticket recorded: a foreign tip is refused with the commit named and the command to move it aside, and submit's `tip_mismatch` remedy no longer tells an executor to repoint a ref another board owns. A same-ticket re-pin over its own earlier candidate still works.
