ref: SQ-38
title: zsh verify wrapper also survives an unbalanced bracket, and the unquoted-glob warning is more accurate
bump: patch
plugins:
  - sidequest
---

The zsh verify wrapper now sets `nobadpattern` alongside `nonomatch`, so an unquoted path with an unbalanced bracket (not just one that simply doesn't match a file) also passes through literally instead of aborting the pinned command with a "bad pattern" error. The unquoted-glob warning at add/update no longer states quoting as the one universal fix: it names the token, explains that zsh used to abort and bash can silently expand it to a different existing path, and recommends quoting only for a tool that globs internally (a test runner such as `node --test`), since quoting breaks a tool that expects the shell to have already expanded the pattern (`tsc`, `pytest`). The warning also stops firing on a URL query string and on a bracket that is already quoted, and now correctly fires on a `--flag=value` path and on a path starting with `../`. The verify-discipline skill's dynamic-route guidance no longer claims only zsh globs brackets; sh and bash do too, and quoting is the safer default everywhere.
