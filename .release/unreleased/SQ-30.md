---
ref: SQ-30
title: The CRAP gate reads config from the measured root, not raw cwd, when --project is omitted
bump: patch
plugins:
  - quartermaster
---

Running the gate from a subdirectory with no `--project` measured the right git toplevel but read `.claude/quartermaster/crap.json` from raw cwd, so it silently fell back to every default (no ratchet, no coverage command, max 6) instead of the project's configured gate. Config now resolves from the same measured root the gate scans, `--project` when given governs config lookup only (the ratchet and the measured tree both follow cwd's own git toplevel), and a coverage command that exits 0 but writes nothing now refuses with the prerequisite error instead of silently scoring a stale lcov already on disk.
