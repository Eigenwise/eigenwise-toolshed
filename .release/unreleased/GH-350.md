title: Board commit handles a staged git mv rename under a glob scope
bump: patch
plugins: [sidequest]

Closes GitHub #350. When a ticket's declared scope was a glob such as `db/migrations/*.sql`, the board `commit` tool failed after a `git mv` rename or `git rm` with `fatal: pathspec '<old path>' did not match any files`. The glob's concrete paths come from `git status`, which lists the old side of a staged rename and a staged deletion, and the commit tool passed that path to `git add --all`, which refuses a path that is in neither the tree nor the index.

- The commit tool now stages only glob-matched paths that exist on disk or in the index, the same rule it already applied to exact declared paths. The staged rename or deletion is still committed.
- When Git still cannot match a declared path, for example an empty declared directory, the refusal says nothing was committed, names the path, and says to put the ticket's file there or remove the path, then call commit again.
