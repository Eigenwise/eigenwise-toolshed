ref: SQ-113
title: "board: an executor can no longer mint its own scope grant, and a live claim keeps the paths it already wrote"
bump: patch
plugins: [sidequest]
---

`hooks.json` now routes `scopeRequest` and `remove`, not only `update`, through the `force-exec-bypass` PreToolUse guard. Before, the guard's rules for an executor's `scopeRequest` with `grant: true` and `remove` with `force: true` were never reached in a real session, so a subagent could pass `by: "orchestrator"` and grant itself a refused path.

MCP `update` with `removeFiles` on a live claim now refuses a path the bound checkout already changed since the dispatch base, and refuses a removal that would empty the declared list (which also dropped the implicit `.release/unreleased/<REF>.md` fragment from scope). Both refusals name the recovery: keep the path declared, or release the claim first.
