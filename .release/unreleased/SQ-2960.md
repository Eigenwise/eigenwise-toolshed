---
ref: SQ-2960
title: "sidequest: a stale worktree is moved into quarantine first and only deleted if it is still clean"
bump: minor
plugins: [sidequest]
---

The worktree sweep no longer deletes anything where it stands. Every reclaim renames the tree into quarantine, reads it again there, and deletes the moved copy only if it is still the clean tree that was classified, so a commit or a file written while the sweep was running keeps the tree parked instead of going with it. A rename never follows a dependency link, and the links are released at the quarantine destination after the move, so a move that cannot happen leaves the source byte-for-byte and record-for-record. Stale worktrees are quarantined whole for two weeks instead of being rebuilt from a patch, so unusual files, links, nested repositories, and empty directories remain intact for recovery. The sweep counts ignored content as data, with installed files under an ignored `node_modules` as the one exception, since worktree setup regenerates that cache; quarantine retention is age alone, so nothing younger than two weeks is deleted; and every delivery path, `sidequest integrate` included, reclaims the candidate worktree in the same command.
