ref: SQ-1815
title: Quartermaster's retro asks what would make your goals easier, not what went wrong
bump: minor
plugins: [quartermaster]
---

The retro used to be a friction hunt: count the denials, the corrections, the interrupts, the commands you kept retyping, then fix those. That misses the improvements that matter most, because the best ones leave no trace. When you need a measurement that doesn't exist yet, nothing errors, nothing gets denied, nobody corrects you, and you only do it once, so every "did this happen repeatedly" threshold skips right past it. Removing friction gets you back to the speed you already expected. Adding a capability moves that baseline.

So the retro now starts by asking what you're trying to get done, then looks for what's missing against that goal, in value order: something you have no way to measure, work you keep doing by hand, knowledge you keep re-deriving, and only then the setup pushing back at you. Findings route to a new destination list that puts a measurement built as a committed skill at the top and permissions near the bottom.

A goal phrased as a standard ("make it reliable", "make sure the output is correct") is the case this is really aimed at. You can't close one of those without a way to check it, so every fix underneath stays a guess and the same argument reopens a week later. The retro now treats that missing ruler as the highest-value thing it can propose.

The self-improvement live rule that quartermaster installs on every workspace got the same treatment, and both it and the retro now send new skills through skill-creator instead of suggesting it in passing. Hand-rolled skill files tend to encode the one example in front of you and end up too vague to trigger when you need them.
