title: "An unscoped write dispatch gets the whole tree instead of silently getting docs/ (GH-341)"
bump: patch
plugins:
  - sidequest
---

A write ticket with no declared files, dispatched with `allowUnscoped: true`, used to bind only the board's `alwaysInScope` paths. On a repo with a `docs/` folder that meant the executor could commit `docs/` and nothing else, its scope requests refused, and the finished work had no clean way to close. `allowUnscoped` now gives the executor the whole tree as its write scope, with `alwaysInScope` paths riding beside it. The MCP and CLI dispatch results carry `writeScope` and the executor briefing's declared-files line says the same thing, for example `write scope: unscoped (whole tree), always-in-scope: docs/`. A scope request inside that dispatch reads as covered. A whole-tree commit in the shared checkout would take every dirty path in it, so an unscoped dispatch that would run there now refuses at dispatch and says to declare the paths. The landed-without-submission guidance now covers a handback the orchestrator cherry-picked: close it with `groomClose --deliveryCommit <the cherry-pick> --deliveryMethod manual`.
