ref: SQ-3183
title: Per-backend context window setting, with Codex capped at 272k because OpenAI bills input above it at 2x
plugins:
  model-gateway: minor
  sidequest: patch
---

Model Gateway has a new `context-window` command that saves one window per backend in `~/.claude/model-gateway/context-window.json`. Defaults: Claude `full` (1M through the `[1m]` alias pins), Codex `272000`, Grok `full`. OpenAI bills input above 272k tokens at 2x, so the Codex cap is enforced by the gateway's sentry: it forces compaction past cap minus 85000 (187000 for the default), which keeps every request, compaction included, at or under the cap. `/v1/models` advertises `min(backend window, cap)` and keeps the `[1m]` ids. A Claude cap is written as `autoCompactWindow` into each project wired at project scope and is refused when no project is wired that way. `CODEX_GATEWAY_CONTEXT_WINDOW` still works as the lowest-precedence Codex fallback. `status` and `doctor` print the effective window per backend with the 2x note, and the catalog rows carry `contextWindow` and `contextWindowNote`.

Sidequest passes each discovered model's `contextWindow` and `contextWindowNote` through to the `models` tool output, and the dashboard's model pickers label discovered models with their window and show the billing note under the availability fallback.
