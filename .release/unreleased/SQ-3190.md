GH-156's `wave_invalidated` refusal with identical baselines no longer reproduces. The fix shipped in sidequest 5.3.4 (SQ-16, PR #185). The real refusal was `surface_overlap` on the ticket's own release fragment, and the old message hid that behind the matching baselines. New tests now cover both reported shapes through `integrate`: a candidate whose parent is the checked-out target head on a per-ticket integration branch, and a candidate that changes only its own release fragment.
