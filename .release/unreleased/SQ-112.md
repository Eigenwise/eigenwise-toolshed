---
ref: SQ-112
title: Quoting advice for bracket paths in pinned verify strings is split by token kind
bump: patch
plugins: [sidequest]
---

The unquoted-glob warning and the verify-discipline skill now give different advice for a literal bracket path and an intended glob. A literal `[id]` path is quoted for tools that take literal paths (tsc, pytest) and quoted and escaped as `[[]id]` for runners that glob their own arguments (node --test), where a quoted bare `[id]` runs 0 tests and still exits 0. An intended `*` or `?` glob is quoted for self-globbing runners and left bare for literal-path tools. A path with a quoted span holding a space (`src/"a b"/[id]/x.test.ts`) is now one token, and a SHELL symlink under another name that resolves to zsh gets the nonomatch preamble.
