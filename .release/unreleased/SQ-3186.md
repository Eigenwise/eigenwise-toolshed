title: "integrate merges around dirty files the delivery never touches (GH-340)"
bump: patch
plugins:
  - sidequest
---

A registered checkout with a service rewriting JSON or log files in the tree was never clean, so every `integrate` refused `integration_target_dirty` over files the delivery didn't change, and the work had to land by hand. Integrate now works out every path the delivery writes (the candidate's range against the target with rename detection off, so a rename's source counts too) before the dirty check. Unstaged edits and untracked files outside that set no longer block: the merge goes ahead and the delivery record lists them in `ignoredDirtyPaths`. A dirty path the delivery writes, and any staged or unmerged state, still refuses, and the refusal now names only those paths and says how many others were ignorable. Single-ticket and wave delivery share the one check. A rollback after a conflict or a failed post-merge gate keeps the ignored edits: the post-merge rollback uses `git reset --merge` instead of `--hard` whenever it has edits to keep.
