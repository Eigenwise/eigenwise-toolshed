---
ref: GH-160
title: The negative-control gate demands markers only for the tests a candidate changed itself, not the tests a merge brought in
bump: patch
plugins: [sidequest]
---

A candidate that merged another branch, such as upstream develop into a fork PR tip or main into a ticket branch, was refused with `negative_control_test_required` for every test the merge carried in, because the gate diffed the whole range from the dispatch base (GH-160). Both the `[sidequest:verify-complete]` comment gate and `submit` now treat a commit as foreign only when a ref of the ticket's integration target reaches it, and walk every other commit as the candidate's own, whichever parent it sits on. A merge the candidate made answers only for lines that no parent had, meaning its conflict resolution and hand edits. So keeping both sides of a union, or an upstream file the merge kept, demands nothing new. A test that only such a resolution changed still needs its `[sidequest:negative-control-test]` line, even when no other commit touched it. A test a later commit renamed or deleted is no longer demanded under its old name.

A shared tree commits on its integration branch, so there the whole range stays the candidate's, as before. A range with no commit from the integration branch keeps the paths and test names it had before. The one addition is a file that only a merge resolution changed. Submit attributes from the dispatch base whatever range base it is given. The refusal and recovery text now say "this candidate added or modified".
