title: "A snapshot board moves to git once the repo exists, and the snapshot walk skips .git and build output"
bump: patch

GH-334. A board first registered before `git init` (or before a parent folder became a repo) kept the filesystem-snapshot adapter forever, so dispatch in a clean 19-file repo refused with "path cap reached 501 paths" and told you to initialize the git repo you already had. `ensureProject` and every dispatch now re-derive the adapter: when the board is on filesystem-snapshot and a `.git` exists at or above its path, it switches to git (never the other way). The dispatch that makes or first sees the switch adds a `Dispatch information: this board switched its source revision adapter from filesystem-snapshot to git ...` warning and records `sourceRevisionAdapterSwitch` on the ticket's dispatch.

The snapshot walk itself no longer counts or hashes `.git`, `node_modules`, `.next`, `dist`, `build`, `target`, `.venv`, `vendor`, or whatever the root `.gitignore` excludes (nested `.gitignore` files and `!` re-includes aren't read). A tree without any of those keeps its existing digest. Path and byte cap refusals now say what the walk skipped and which top-level folders held the paths it counted, e.g. `This walk skipped .git, node_modules; the most paths it counted were under src (6), docs (3), . (1).`
