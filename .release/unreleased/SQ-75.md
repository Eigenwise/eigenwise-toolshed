ref: SQ-75
title: A crossed checkout binding no longer survives release and solo redispatch
bump: patch
plugins: [sidequest]
---

Follow-up to GitHub #298. When siblings launched together had both claimed against each other's checkouts, the claim-time correction could no longer run, and the crossing outlived every recovery. Live-claim recovery (`dispatch` with `recoveryEvidence`, `claimHolder`, and `worktree`) refused with "is bound to a different worktree and cannot be rebound". A release followed by a solo redispatch resumed the retained checkout, which was the sibling's, so one executor started on the other ticket's commit. Recovery now rebinds the claim to the named registered checkout of the project. It refuses only when another live ticket holds that checkout and its HEAD is not this claim's own commit, or when the checkout carries another ticket's commits. The rebind is recorded as `worktreeCorrection`. A release made from inside the executor's checkout keys the retained continuation to that checkout. If that checkout is not a registered checkout of the project, the retained binding is dropped. A continuation resumes a retained checkout only when its HEAD is this ticket's own board commit, checkpoint, submission, or pinned candidate, and no commit in the range belongs to another ticket. Otherwise the next dispatch gets a fresh checkout and names the reason.
