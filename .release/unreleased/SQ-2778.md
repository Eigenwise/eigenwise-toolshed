ref: SQ-2778
title: A landed candidate whose submitter cannot be identified now closes as delivered without review provenance
bump: patch
plugins:
  - sidequest
---

A candidate can reach the point where its bound review ran independently on that
exact commit, and the only thing missing is the submitting attempt's own runtime
identity, which nothing can add after the fact. Every terminal state the board
offered for that case was false: integration refused, and the one alternative it
named recorded the candidate as abandoned, on work that was already on the
integration branch and shipped in a release.

`groomClose` with the delivery commit now records that honestly. The board
verifies the landing itself rather than trusting the caller: the commit has to be
reachable from the recorded integration target, and every declared candidate path
has to be byte-identical between the commit and the branch tip, because ancestry
alone says the work arrived, not that it survived. A path that differs refuses and
names itself, so a partly landed candidate cannot use this door.

The closure records its own outcome, `delivered-without-review-provenance`,
carrying the refusal it came from and the verification that was performed, so
these are findable later and never read as a normal integration.

The gate is unchanged. This door is open for that one unrecoverable shape only:
a review that never ran, a reviewer that never bound a runtime, and a self-review
all still refuse, because re-dispatching a review fixes those. `abandonSubmission`
keeps its meaning, a candidate genuinely discarded.
