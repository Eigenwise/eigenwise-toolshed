ref: GH-171
title: "Verify wrapper no longer aborts on unquoted [param] paths under zsh, and pinned verify strings warn about unquoted globs"
bump: patch
plugins: [sidequest]
---

The verify-capture wrapper writes setopt nonomatch into the generated script when the selected POSIX shell is zsh, so an unquoted dynamic-route path like [id] passes through literally instead of aborting the pinned command with "no matches found". A pinned verify string with an unquoted path containing glob metacharacters ([ ] * ?) now also gets a warning (not a refusal) at add/update and in the executor briefing, naming the token to quote.
