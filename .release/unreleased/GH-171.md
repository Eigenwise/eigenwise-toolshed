ref: GH-171
title: "Verify wrapper no longer aborts on unquoted [param] paths under zsh, and pinned verify strings warn about unquoted globs"
bump: patch
plugins: [sidequest]
---

The verify-capture wrapper writes setopt nonomatch nobadpattern into the generated script when the selected POSIX shell is zsh, so an unquoted dynamic-route path like [id] passes through literally instead of aborting the pinned command with "no matches found" or, for an unbalanced bracket, "bad pattern". A pinned verify string with an unquoted path containing glob metacharacters ([ ] * ?) now also gets a warning (not a refusal) at add/update and in the executor briefing; the advice quotes the token when the verify tool matches paths itself (e.g. a test runner such as node --test), and skips that advice when the tool expects the shell to have already expanded the glob into literal paths (e.g. tsc, pytest), where quoting would turn a passing run into a hard error.
