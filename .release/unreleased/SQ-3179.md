ref: SQ-3179
title: "Boards are only created for real project folders"
bump: patch
plugins:
  - sidequest
---

Any hook or tool call used to mint a board for whatever folder it ran in, so Codex scratch dirs, temp run dirs, the local CRAP gate dir and even Sidequest's own storage folder showed up as boards. A call that names no project now creates a board only for a git repository root (or reuses a board that's already registered). Naming an absolute path still registers a plain non-git folder like a notes vault. Neither path creates a board for a missing folder, anything in the system temp dir, or anything under `~/.claude` including the Sidequest home. The refusal starts `not a project root:`, names the path and the rule, and on MCP lists the registered boards to pass as `project` instead. The dashboard API returns that refusal as a 400. A throwaway `SIDEQUEST_HOME` that itself lives in the temp dir (tests, isolated verification) still accepts temp fixture folders. The `projects` listing (MCP, CLI `projects --json`, dashboard API) now marks a board whose folder is gone with `missingPath: true`. Nothing gets archived or deleted automatically.
