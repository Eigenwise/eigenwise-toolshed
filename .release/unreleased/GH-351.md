---
ref: GH-351
title: Keep the notifications row bounded and out of the ticket write transaction
bump: patch
plugins: [sidequest]
---

Closes GitHub #351. Notifications live in one store row, and only read entries were ever pruned, so a busy board's row grew to 9.46 MB with 6,062 unread entries. Every ticket event parsed and rewrote it inside the ticket's write transaction, holding the SQLite write lock for 320-470 ms instead of about 11 ms; six concurrent writers saw a median of 1.77 s and "Sidequest database stayed locked" errors.

Unread notifications are now capped at the newest 200 and dropped after 14 days (`SIDEQUEST_NOTIFICATIONS_MAX_UNREAD`, `SIDEQUEST_NOTIFICATIONS_UNREAD_MAX_AGE_DAYS`); pending reminders are exempt. A notification is written in its own short transaction after the event commits, and dropped with the event if it rolls back; a crash between the two loses only the notification. A store opened with a notifications row over 2 MiB is pruned on that first open.
