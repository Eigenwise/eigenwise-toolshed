ref: SQ-25
title: the diverged-upstream recovery names the delivery it accepts, and MCP integrate can complete it
bump: patch
plugins: [sidequest]
---

The `expected_upstream_diverged` refusal's recovery text named `groomClose` with `deliveryCommit` but not the `deliveryMethod` the waiver actually requires, so following it verbatim refused again; it now spells out `deliveryMethod: "manual"` and the CLI flags, and matches an assertion that keeps the two from drifting apart again. MCP `integrate` previously dead-ended on the identical recovery even when passed `deliveryCommit` and `deliveryMethod`, because two separate internal checks it runs both dropped `deliveryMethod` before reaching the same validation `groomClose` already passed correctly; both now forward it. The waiver itself is now gated on the pinned candidate being unreachable from the current upstream, matching the same non-reachability test the delivery record uses, rather than opening for any named method. A mistyped `deliveryMethod` is validated before the diverged-upstream check runs, so it is refused by name instead of being reported as a diverged upstream.
