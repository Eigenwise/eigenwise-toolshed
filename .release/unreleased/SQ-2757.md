---
ref: SQ-2757
title: "A repair inheriting a rejected candidate can submit against that candidate's boundary"
bump: patch
plugins: [sidequest]
---

The repair flow after an oracle rejects a candidate had no legal submit base: the
inherited commits tripped `duplicate_submission`, and every other boundary tripped
`unrecognized_base`. A repair ticket linked `related` to a source whose submission
mirror records `review.outcome: rejected` now treats that rejected candidate as an
approved submission boundary, so plain `submit` selects it and the range carries only
the repair's own commits. The boundary still needs the recorded rejection, the link,
and real git ancestry, so an active or unrelated candidate refuses exactly as before.
Both refusals now name the base that clears them instead of dead-ending.
