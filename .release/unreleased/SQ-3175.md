---
ref: SQ-3175
title: Sweep-report tests recalibrate their wait bound at each wait, not once at collection
bump: patch
plugins:
  - sidequest
---

The hooks test suite's shared `waitForPath` helper scaled its default bound against a `node -e ''` baseline measured once when the test file loaded. A Windows CI runner that got busy later, after collection, could outrun that stale baseline and hit the 5000ms floor even though a single hook run legitimately cost longer under load, failing the sweep-report wait with no code change involved. The baseline is now re-measured fresh at each call to `waitForPath` that doesn't pass an explicit budget, so the bound tracks load at the moment of the wait instead of at file load. The 5000ms floor and the explicit-budget timeout control are unchanged.
