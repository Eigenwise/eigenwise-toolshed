---
ref: SQ-17
title: Read a negative-control marker field by field
bump: patch
plugins: [sidequest]
---

A negative-control marker whose `target=` value contained a semicolon — two paths joined with `;`, or prose like `a; b` — stopped the parse at that semicolon, and the completion gate refused it with the message it gives a marker that names no evidence at all. Each field is now read up to the delimiter that introduces the next one, so a semicolon inside `target=` is data, and a marker that genuinely cannot be parsed is quoted back with the field it stopped at instead of reading as though nothing was posted.

The same check attributed a hunk inside an `it.each` or `test.each` table to the nearest preceding plain `it(`, which demanded negative-control evidence for a test the diff never touched. A table-driven test is now recognised by the name that follows its table, so the hunk reports that test.
