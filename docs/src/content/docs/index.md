<section>
  <p class="hero-kicker">Choose by the problem in front of you</p>
  <div class="shed-grid">
    <article class="shed-card card">
      <h2>Setup keeps repeating</h2>
      <p><a href="./getting-started/quartermaster/">Quartermaster</a> proposes a project setup, keeps active Toolshed installs current, and checks workspace health.</p>
    </article>
    <article class="shed-card card">
      <h2>Claude keeps re-learning the repository</h2>
      <p><a href="./getting-started/codebase-mapper/">Codebase Mapper</a> keeps a small project map nearby and refreshes it as the code changes.</p>
    </article>
    <article class="shed-card card">
      <h2>Rules get forgotten or apply everywhere</h2>
      <p><a href="./getting-started/live-rules/">Live Rules</a> loads project guidance when the matching work starts.</p>
    </article>
    <article class="shed-card card">
      <h2>Side work gets lost</h2>
      <p><a href="./getting-started/sidequest/">Sidequest</a> turns work into owned tickets, dispatches independent changes, and checks results before integration.</p>
    </article>
    <article class="shed-card card">
      <h2>You want another model in Claude Code</h2>
      <p><a href="./getting-started/model-gateway/">Model Gateway</a> adds supported ChatGPT/Codex and Grok subscription models through a local gateway.</p>
    </article>
    <article class="shed-card card">
      <h2>Usage is hard to see</h2>
      <p><a href="../observability/">Observability</a> records selected metadata locally, with per-project opt-in and optional sinks.</p>
    </article>
  </div>
  <p>These plugins are independent. Quartermaster is the guided entry point, not a prerequisite. Install one plugin directly when you already know the job.</p>
</section>
