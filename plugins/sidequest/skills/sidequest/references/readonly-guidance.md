# Read-only review and audit guidance

Sidequest routes formal candidate reviews, repository audits, and shortcut-debt reports through the existing readonly `review-audit` category. They report findings only. They never edit the repository, create a ledger, run a migration, or start a sweep.

These reports need Sidequest installed in the host. When it is unavailable, say the routed report capability is unavailable rather than pretending to have board integration.

## Bounded live advice

For a named architectural risk or contested approach worth the cost, the orchestrator may assign a
readonly advisor before expensive implementation or tests. Select a suitable advisory capability by
its live taxonomy description and preserve that profile's routing. A readonly feasibility/design
investigation can fit; its category name alone does not authorize candidate acceptance. If no suitable
category or native messaging tool is available, report the missing capability. Do not invent a role,
guess an address, change profiles, or use formal `review-audit` binding for a moving draft.

Declare the advisor's question, producer, authorized source paths/snapshot, inspection limits and
budget in its ticket. The builder and advisor can communicate directly through available native
messaging to their authentic host identities. The producer keeps ownership of the patch, focused
regressions, local quality measurement, final capture and submission. Advice can arrive while that
work proceeds. Send concrete findings and scope/resource/authority decisions, not routine checkpoint
or acknowledgement relays. An advisor has no write, acceptance, release or resource-transfer authority.

Record the actual inspected file hashes, snapshot revision when present, limits and unresolved
findings. Hash the inspected bytes, not a nearby commit while the working files differ. If a file moves
during inspection, mark that finding partial or re-inspect an explicitly authorized frozen snapshot.
Report unavailable paths as a visibility block. Draft findings remain advisory. Neither a clean draft
report nor a checkpoint accepts a candidate or releases the producer's claim. Source inspection
outside a declared collaborative role stays prohibited; this exception does not authorize orchestrator
peeking or self-review.

## Candidate diff review

Use this only for a submitted candidate that needs independent scrutiny. Create a readonly `review-audit` ticket with an immutable `reviewTarget`: the submitted ticket ref and its exact submitted commit (or source revision for a non-Git artifact). Never bind a working tree, a live claim, or a retargeted candidate. The isolated reviewer reports evidence and closes through the bound-review flow.

At final review, match earlier inspected hashes to the immutable candidate before reusing those notes.
Reuse byte-identical inspected material; check the settled delta, unresolved findings and authentic
source/reviewer execution identities. Changed or unobservable material needs fresh inspection. Consume
genuine compatible verification captures without rerunning a suite merely for reviewer identity.
Existing exact-candidate, independence, capture and delivery guards still decide acceptance. Advisory
notes and prose about execution never replace those guards or prove an unexecuted check passed.

## Repository audit

Create a readonly `review-audit` ticket with a named scope such as `plugins/sidequest/` or `src/billing/`. Ask for concrete, source-backed findings: code to delete, existing local reuse, standard-library or native-platform replacements, speculative behavior to remove, and smaller direct shapes. Each finding names its file and line, why the current code costs something, and the smallest safe change. No automatic edits.

## Shortcut debt

Create a readonly `review-audit` ticket with the source directories to inspect. Scan actual source comments for `whittle:` markers. Report each deliberate shortcut with its file and line, known ceiling, observable upgrade trigger, and replacement. A missing ceiling or trigger is itself a finding. Do not invent either one, require a marker for every simplification, or move results into a ledger.

## Measurement

Use Observability for absolute measurements. Call a gain unmeasured unless a matched baseline supports the comparison. Absolute metrics do not establish causal gain. Do not reuse static headline figures or private workflow data as report evidence.
