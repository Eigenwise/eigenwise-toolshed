# Modules and plugin catalog

Last Updated: 2026-10-01

## Plugins

- **Sidequest** (`plugins/sidequest`): local orchestration board, typed SQLite store, MCP server, CLI, lifecycle hooks, and dashboard. Core modules are `src/lib/store.ts` (a facade over `src/lib/store/` layers), `db.ts`, `mcp.ts`, `server.ts`, `agentsync.ts`, `context-packet.ts`, `mcp-read.ts`, `mcp-shared.ts`, `prepared-dispatch.ts`, `source-revision-capability.ts`, `worktrees.ts`, `commit-scope.ts`, and `src/bin/`. `src/lib/kernel/` owns pure attempt transitions, submission admission, review binding, assembled-wave delivery decisions (`kernel/wave.ts`), and worktree lease decisions; store and transport modules supply observed facts and persist accepted transitions. `store/submissions.ts` parks immutable candidates, preserves rejected ones, and records integrated replacement evidence. `store/project-watch.ts` gives each watch a project, session, and actor identity so notifications never spill into another board. The `plugins/sidequest/scripts/owned-process-tree.js` and `plugins/sidequest/scripts/owned-phase-supervisor.js` pair owns subprocess groups through timeout and cleanup. `src/lib/hook-timeouts.ts` holds the WorktreeCreate hook budget and setup headroom that `hooks/worktree-create.js` inlines, so worktree setup gives up before Claude Code's hook timeout kills it. `agentsync.ts` renders the stable implementation, diagnostic, and read-only executor definitions from `scripts/_exec-template.md`, including shared-tree preservation and handback guidance; `scripts/generate-bundled-agents.mjs` writes those definitions into the packaged `agents/` directory, while normal SessionStart and CLI sync paths migrate marked legacy generated files instead of recreating them.
- Sidequest lifecycle additions: `src/lib/store/routing.ts` shares `dispatchReadOnly` for explicit cross-provider readonly eligibility. `store.ts` supplies `ticketIntegrationTarget` and `ticketIntegrationTargets` to submission, wave, MCP and CLI delivery paths so recorded per-ticket targets remain authoritative. `src/lib/store/dispatch.ts` reconciles launched-but-never-claimed primary-session dispatches at SessionStart, and its `claimGraceMs` is the single retirement deadline every unclaimed-attempt route (`dispatch`, `groomClose`, `pulse`, `groom-close`) reads. Its crossed worktree binding now parks the displaced sibling's retired creation record on the winner (`crossBoundWorktree.parkedCheckout`) instead of dropping it, and a later claim that adopts the same observed checkout settles that parked record onto the new holder. `src/lib/store/submissions.ts` records typed `done.verify` evidence for commandless working-tree or external-deliverable delivery (`externalDeliverableCloseout`) while command/suite requirements remain capture-bound, and its `applyDeliveryAwaitingContentCommit` keeps an `apply`-mode delivery's `groomClose ... deliveryCommit` binding retryable on verifier failure. `deliveryRevisionPreflight` lets `recordDeliveredSubmission` prove a rebased or squash-merged candidate at a named `deliveryRevision` commit instead of the reachable delivery commit itself, with `resolvedPaths` required for every path the reviewer resolved by hand and refused when the delivery commit is already reachable on its own (PR #146); a reachable-but-merged delivery that isn't a `deliveryRevision` proof still falls back to `git patch-id`-equivalence over the submitted range for a squash merge whose single resulting commit carries no per-candidate-commit patch (SQ-3113). `mcp-lifecycle.ts`'s `inheritedRejectedAdmission` admits a `related`-linked repair's range that inherits an oracle-confirmed rejected candidate. `mcp-shared.ts`'s `resolveLifecycleProject` resolves an omitted-`project` lifecycle call's board from the caller's own claim or worktree binding. `worktrees.ts`'s `retainedWorktreeResumeDecision` refuses to resume a retained checkout stuck mid a cherry-pick, merge, revert, rebase, or bisect, and its WorktreeCreate callbacks are generation-scoped against `stale_attempt`/`missing_attempt`. `agentsync.ts`, `mcp-collaboration.ts`, and `hooks/force-exec-bypass.ts` support reduced Agent schemas by omitting `name` and `mode`; `hooks/bind-runtime-identity.ts` and the store require hook-reported `agent_id` and `permission_mode` `bypassPermissions` before the first claim.
- Sidequest process and safety modules: `src/lib/git-process.ts` is the one git child-process wrapper (`windowsHide: true` by default, a 256 MiB output cap for `git ls-files` on large repos); every git call in the store and hooks routes through its `execFileSync`/`execFileText`. `src/lib/board-mcp-liveness.ts` writes a pid-keyed liveness marker per running Board MCP server (`~/.claude/sidequest/tmp/state`, keyed by session id and canonicalized project so a rotated session id from `/clear`, resume, or compaction still matches) and `observeBoardMcp` reads it back as live/rotated/exited/absent/unreadable; `hooks/force-exec-bypass.ts` uses it to tell a raw-Agent dispatch attempt whether the board server it needs has actually exited versus never having registered, and to steer toward `/mcp` reconnect instead of a CLI fallback. `src/lib/denied-tools.ts` normalizes and matches a board's, category's, or read-only-only `deniedTools` list (a bare MCP server prefix denies every tool on it, and the list can never deny the Sidequest board tools an executor needs to claim and close); `src/hooks/guard-denied-tools.ts` is the PreToolUse hook that enforces it per-ticket at call time, since packaged agent frontmatter is generated once and cannot carry one board's settings. `src/hooks/shared/read-only-shell.ts` is a lexical (not sandboxed) shell-write guard for read-only executors: it tokenizes a shell command into pipeline segments, resolves redirect and mutating-command targets (including `git`'s mutating subcommands and in-place `sed`/`perl`) against the current and enclosing worktree/checkout roots, and refuses the first one that lands inside the checkout; `force-exec-bypass.ts` is its consumer. `src/hooks/agent-dispatch-state.ts` is the SubagentStop hook that writes each dispatch's ref, outcome, and terminal time into its worktree's linked `.git` directory (`sidequest-dispatch.json`, invisible to Git) so a project-level reaper keyed on the orchestrator's pid can find and stop anything the executor started in that worktree after the executor itself stops.
- Sidequest board admission and scope: `store/projects.ts` `boardRootRefusal`/`registerProject` refuse an implicit board for a folder inside the Sidequest home, the Claude config directory, system temp (unless the store itself is a throwaway under temp), or a non-git folder; an explicitly named plain folder still registers, and an already-registered board is reused (SQ-3179). `hooks/board-first-reminder.ts` uses the same refusal to stay silent there, and otherwise sends a routed-board reminder or a "no board yet" hint once per session for prompts that look like work requests. `ensureProject` and dispatch (`takeSourceRevisionAdapterSwitch`) migrate a `filesystem-snapshot` board to `git` once the folder becomes a repository, never the reverse, and the dispatch result reports the switch once (GH-334); the snapshot walk in `source-revision-snapshot-child.ts` skips `SNAPSHOT_SKIPPED_NAMES` (`.git`, `node_modules`, build output, `vendor`) and root `.gitignore` rules, and a cap refusal carries bounded skipped/counted samples. `store/dispatch.ts` gives an `allowUnscoped` write dispatch the whole tree (`WHOLE_TREE_SCOPE` `**` in `commit-scope.ts`, recorded as `unscopedOverride.writeScope`) with the board's `alwaysInScope` paths beside it, and refuses that in the shared checkout (GH-341). `store/candidate-refs.ts` moves a board's `refs/sidequest/SQ-n` candidate refs under `refs/sidequest-archived/<board>/` on archive and back on restore, so a new board's SQ-n cannot collide (GH-378).
- Sidequest closeout: `store.ts` `readOnlyChangesOutsideArtifactRoots` lets a read-only `done` pass over paths under its category's `artifactRoots` and refuses anything else in declared scope (GH-332). `store/submissions.ts` `integrationTargetDirt` lets integrate proceed around unstaged or untracked paths the delivery never writes (GH-340, reported as `ignoredDirtyPaths`), while staged or unmerged state still blocks, and a direct claim runs the ticket's current verify rather than a stale dispatch pin, with its own capture invocation (GH-377). `test:files` in `plugins/sidequest/package.json` runs `typecheck` first, so a `tsc` error in a named test file fails a pinned verify (SQ-3204).
- Sidequest routing defaults: `category-defaults.ts` seeds GPT-6.1 Sol (`codex-gpt-6-1-sol`) as the fallback for coding.hard, experiment and spike categories (seed revision 9) and `categoryWithCurrentCodexRoutes` rewrites stored rows still naming the retired Sol/GPT-6 ids, keeping Astra only for frontier categories; `store/routing.ts` `getCategoryRoutePairs` skips disabled categories and keys pairs by `readonly`, so only routed readonly/write pairs get generated executors. The dashboard's `model-windows.ts` shows each backend's window in settings.

- **Observability** (`plugins/observability`): metadata-only lifecycle telemetry. `hooks/observability.js` observes eight lifecycle events, `lib/observability/` holds the schema, store, ingest, outbox, OTLP sender, and ensure worker, `bin/` holds the observer, statusline, setup, and reports, and `observability/sinks/` selects grafana, otlp, posthog, or none. Setup provisions dashboards from the opted-in project registry and treats dashboard mounts as container freshness. Observer launch is never-downgrade like Model Gateway's: `ensure.js` resolves the newest installed plugin version's `bin/observer.js` from the plugin cache and an older session's ensure leaves a newer live observer untouched (after a stale session kept resurrecting pre-fix observer code). `bin/project-telemetry.js` and `verify-project-telemetry.js` know that Claude Code 2.1.282+ ignores export variables in project and local settings, so they report user-level export state and offer `userExportCommand` instead of claiming project settings can enable it (GH-372). Its adapters read Model Gateway and Sidequest. `observability/sinks/grafana/model-prices.js` applies per-request Astra short/long pricing and `dashboard-generator.js` adds unpriced model token usage without treating it as USD. Split out of Workbench; the `workbench-observer` service name and `workbench_` attribute prefix stayed, because shipped Grafana queries and existing data depend on them.
- **Model Gateway** (`plugins/model-gateway`): local Claude Code model registry, proxy launcher, readiness/doctor state, schema-4 provider catalog, and ChatGPT/Codex and Grok subscription routing. `lib/process-supervision.js` and `lib/request-worker.js` recover the shared proxy when an active request finds it unavailable; version handling is never-downgrade (`lib/runtime.js` `resolveNewestInstalledCliPath`/`canReplaceInstalledCliPath`): an older CLI's `ensure` leaves a newer serving shim running, and the shim `/restart` refuses an older worker script. State-file writes (catalog, dispatch-route cache, pin cache, Grok auth) go through `lib/atomic-file.js`, which retries replaces that lose to a concurrent reader and sweeps stale `.tmp` siblings, and readiness metadata is written separately from model entries so consumers can explain an unavailable provider without advertising its routes. `lib/runtime.js` `resolveGatewayModelPolicy` is the one per-model window table (backend window, advertised window, `[1m]` picker alias, sentry trigger, now including `gpt-6.1-sol`) that the shim, the compaction sentry in `lib/request-worker.js`, and `doctor` all read. Context windows are one saved setting per backend (`claude`, `codex`, `grok`) in `context-window.json` (`readContextWindowSettings`; defaults Claude `full`, Codex 272000 because OpenAI bills input above 272k at 2x, Grok `full`; legacy `CODEX_GATEWAY_CONTEXT_WINDOW` still works below a saved value), set with `model-gateway.js context-window --claude|--codex|--grok <tokens|full>` (`lib/context-window.js`). A gateway cap compacts at the cap minus `CAP_COMPACTION_MARGIN` through the synthetic-413 sentry; a Claude cap is written to the project-wired `autoCompactWindow` only where the gateway owns that value. The shipped Sonnet pin is `claude-sonnet-5-5[1m]` (`claude-sonnet-5[1m]` is in `RETIRED_SHIPPED_PINS`), and `settings-wiring.js` `syncRegisteredProjectPins` rewrites a gateway-owned pin only in projects that already hold that key, so a refresh never newly wires a project. Supervision kills only processes proven to be this install's or a same-marketplace/plugin cache sibling's: ownership probes (`netstat`, PowerShell `Get-CimInstance`, and POSIX `ps -ww`) run asynchronously with a bounded timeout; unknown or foreign owners are left alone, and proxy recovery requires a matching binary plus descendant ownership proof. `lib/windows-detached.js` launches the supervisor through WMI outside the calling hook's process tree and Job Object; `lib/lifecycle-diagnostics.js` keeps bounded lifecycle records in `~/.claude/model-gateway/logs/lifecycle.jsonl` that `doctor` reads to explain an observed exit versus no evidence. Supervisor shutdown waits for pending PID-record writes and supervised children, including fixture shutdown signaling. Ownership probes default to 8 seconds on Windows and 2 seconds elsewhere; exhausted deadlines remain unknown. `lib/codex-upstream-state.js` owns atomic persistent rejection and transient outage evidence. `createRouteTelemetry.finish` in `lib/request-worker.js` makes one terminal readiness decision and canonical `codex_gateway.route` span across retries, after context-error normalization. Completed Codex inference clears both records; transient evidence expires after 60 seconds without reader mutation, while attributed auth rejection takes precedence. Expiry establishes only absence of recent failure evidence; Sidequest's existing catalog refresh can lag five minutes. Compaction handling in `lib/request-worker.js` detects Claude's compaction prompt, retries a buffered Codex stream before exposing output, caps buffering, and records only bounded outcome, upstream status/error, terminal code, and usage counters in route telemetry; `lib/usage-observability.js` keeps the related usage records body-free. A stream that loses its `message_stop` counts as finished only when its own `message_delta` carried an end-of-generation `stop_reason` (`end_turn` or `stop_sequence`), no content followed the stop, and no content block is still open; every other stop reason, `max_tokens` and `tool_use` included, is re-inferred rather than delivered, because a truncated compaction body silently replaces the whole conversation. Lifecycle control is authenticated: `lib/control-auth.js` gates `/restart` and `/drain` on a 0600 token minted before the supervisor listens, and `lib/release-verification.js` checksum-verifies a downloaded proxy before it replaces the installed binary. `lib/shim-state.js` is the one reading of shim state (`running-ours`/`running-foreign`/`starting`/`stopped`) that `commands.js`'s `status`, `doctor`, and `ensure` all import instead of probing separately, so they cannot disagree about whether the shim is up.
- **Live-rules** (`plugins/live-rules`): atomic rule storage and injection into prompts and edits. `hooks/session-start-rules.js` also runs at SubagentStart, keyed per subagent under the parent session, so native subagents get startup-scoped rules once.
- **Release automation** (`scripts/release`): `cut.mjs` plans and prepares or explicitly directly publishes a release, `finalize.mjs` derives tags from manifest changes on the exact merged publish-branch commit, and `guard.mjs` enforces `dev`/`main` invariants plus per-path sync-back waivers. `lib/promotion.mjs` prints promotion and sync PR commands; `lib/publishlock.mjs` wraps the Sidequest publish lock, which serializes participating publishers but cannot provide an atomic remote branch-head compare-and-set.
- **Codebase-mapper** (`plugins/codebase-mapper`): generates atomic project maps, injects the index at session start, and enforces announced map updates through declarative `PreToolUse: Skill` and `Stop` hooks.
- **Quartermaster** (`plugins/quartermaster`): workspace setup and capability passes grounded in session history. Ships the `setup` and `resupply` skills. The miner streams recent transcripts into a bounded signal aggregate: what each session was for (title, opening ask, any `/goal` and whether it was met, a `humanDriven` flag, the areas of the tree touched) plus attribution, habits, and friction (denials, interrupts, corrections). `lib/scan.js` resolves the window, `lib/stream.js` streams records into `lib/signals.js`, which preserves raw host denial kinds and adds `friction.denials.meaning`: `permission-rule` can represent a hook policy block and cannot establish permission-rule provenance or justify allowlisting by itself. `lib/catalog.js` reads local plugin catalogs for recommendations, and `lib/state.js` keeps per-session tallies and the decision ledger that `verify` checks recommendations against. `bin/quartermaster.js` exposes `mine`, `status`, `catalog`, `decisions`, `verify`, `mark-resupply`, and `decline-resupply` (a decline resets the accumulation window so offers stay quiet until evidence re-accumulates). Besides the SessionStart nudge, `hooks/stop-resupply-offer.js` is a Stop hook that blocks the turn once per session when a resupply is overdue, forcing the offer at a real pause; it keeps its own `QUARTERMASTER_OFFER_HOURS` cooldown separate from the nudge's `lastNudgeAt`. It also carries the project bootstrap, Toolshed update, and health-check role that Workbench held until that plugin was folded into it: the `setup`, `update-toolshed`, and `toolshed-doctor` skills, `lib/project-settings.js` as the workspace settings writer (agent teams, compaction window, Sidequest compaction policy), and `bin/update-toolshed.js`, which hands Model Gateway updates to the stable `~/.claude/model-gateway/update.js` launcher installed from the newest active registry entry. That updater records nothing itself and resolves Observability from the install registry rather than importing it, so it works standalone. `lib/gateway-health.js` parses Model Gateway `doctor` output for the SessionStart freshness hook and the doctor skill. `hooks/stop-update-check.js` refreshes stale marketplace data at Stop and reports remote updates or newer installed code without installing or blocking. `lib/project-settings.js` reports the effective `autoCompactWindow`; setup offers 325000 when unset, while doctor reports it read-only. `lib/crap-core.cjs` now scans script-family source with its own tokenizer (`scanToken`, brace and branch counting) so a function lizard truncates at its parameter list is scored over its real body (GH-315). Setup also seeds an adapted reuse-first implementation baseline and self-improvement live rule into each approved workspace, and can propose `lib/crap.js`'s language-agnostic CRAP gate (`bin/quartermaster.js crap`, Node stdlib only, needs `lizard` on PATH) as a seeded `.claude/quartermaster/crap.json` plus live rule once approved.


The six registered plugin packages use a manifest such as `plugins/model-gateway/.claude-plugin/plugin.json`, skill files under `skills/<name>/SKILL.md`, and `hooks/hooks.json`. Hook runtime files are committed JavaScript.

Model Gateway's `lib/tool-schema-compat.js` performs bounded Codex-only schema adaptation after deferred hydration, with local refusal for unsupported affected shapes and unchanged Anthropic bytes. `process-supervision.js` confirms failed proxy health through fresh connections before recovery. Its process-environment diagnostics preserve supported CLI behavior and explain forced Desktop routing limits. Sidequest's cleanup gates cover sweep and failed-creation recovery using recorded dependency-link provenance; explicit read-only base selection is honored. Native Sidequest and Quartermaster guidance gives the orchestrator ownership of the improvement decision and keeps read-only review/audit/debt reports native to Sidequest.

## Shared support

`plugins/test-support/windows-hide.js` scans plugin JavaScript for child-process calls missing `windowsHide: true`. Quartermaster, Observability, and Model Gateway consume it in their tests.

## Dashboard modules

The dashboard has a project rail, toolbar, board views, archive, ticket/settings/notification surfaces, a guided tour (`app/src/lib/components/tour/TourOverlay.svelte`, `app/src/lib/tour/steps.ts`, `app/src/lib/state/tour.svelte.ts`), and a polling state layer. It communicates with the local server through `app/src/lib/api.ts`; it does not access SQLite directly.
