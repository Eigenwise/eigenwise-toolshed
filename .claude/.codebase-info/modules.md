# Modules and plugin catalog

Last Updated: 2026-10-21

## Plugins

- **Quality Gate** (`plugins/quality-gate`): dedicated AST complexity and per-body coverage owner. `lib/compiler.mjs` resolves TypeScript 7 from the measured project, then the plugin dependency; `lib/core.mjs` measures independently owned JS/TS bodies. Its native inspector preload captures precise V8 coverage and executed script bytes in the same session. Runtime ownership uses exact AST ranges, never export names, sibling order or proportional scaling. Direct sources must match captured bytes; transformed sources require an authentic single-source embedded map with matching source path/content and supported boundaries. Native compiler block ends use exact last-byte correspondence first, then the exclusive-end closing token only when its own exact compiler segment and byte match; unsupported or ambiguous boundaries remain unverified. Raw V8 reports, installed tsx maps with null source content and unmapped Sidequest builds remain unverified. `lib/measure.mjs` reuses this core for explicit external-new admission: `measureFiles(files, { projectRoot, base, coverageDirectory, externalNewFiles = [] })`. Each declared external body is enforced as new with `admission: "external-new"`, canonical absolute `relativePath`, raw SHA-256 `sourceHash` and resolved Node/TypeScript `evaluatorVersions`. External-only measurement avoids Git; repository selections retain their explicit base. `bin/quality-gate.js crap --project <root> --base <revision>` consumes project-local configuration and LCOV with same-byte SHA-256 provenance plus executable-line completeness, writes local receipts, and reports missing coverage as unverified. Python compiles exact source to inventory independently owned executable lines; every line must have a DA record, including explicit zero hits. Missing, excluded or ambiguous records remain unverified. Other LCOV adapters lack an independent completeness inventory and remain unverified; supported JS/TS uses native V8 measure. `lib/python.mjs` invokes the stdlib Python adapter `lib/python/crap_adapter.py` with isolated Python; adapter version `python-ast-1` qualifies test oracles from source and owns nested methods, closures and lambdas separately. Shared-line ownership stays unverified. PHP/Vue use bound Lizard rows. Physical source fingerprints select all new or modified independently owned bodies, including formatting/comment edits and equal/lowered-complexity legacy edits; untouched legacy remains outside admission. Git readers preserve raw source bytes. Python includes decorators/trailing indented comments and excludes independent child byte spans in source order, so a child-only edit cannot charge its untouched parent. PHP/Vue bound spans retain physical text; overlapping ownership stays unverified. Existing opt-in and Python policy defaults are unchanged. `lib/python/policies.json` enumerates default `python-ast-1` and opt-in `python-radon-6.0.1-oracle-1`, selected through CLI/config/protocol. The native policy counts ordinary assertions without traversing predicates/messages; qualified source-named or exact selected helper oracles traverse those decisions without the assert surcharge. Native-only nested-class boundaries isolate both decisions and assertion inventory while keeping independent methods/lambdas and default behavior. Exact selectors are authoritative; fixture/setup precedence and validation remain enforced. `quartermaster crap` now delegates here (SQ-3712). `lib/lcov.mjs` `expandCommandVariables` expands `$VAR`, `${VAR}` and `%VAR%` in `coverageCommand` before spawning on every platform (GH-543). `lib/reuse-signals.mjs` adds informational reuse signals to the text and `--json` (`signals`) report, including `--cc-only`, never changing verdict, exit code or receipts (SQ-3719, after ponytail's band): `DUPLICATE?` when a `new` body's normalized name (lowercase, `_` and `-` stripped) matches a top-level JS/TS/Python definition in another file found by one `git grep` over HEAD, and `CALLERS OPEN` when a baseline body absent at HEAD (collected by `changedMetricsAgainstBase` through `removedMetrics`, with deleted files from `crap-inputs.mjs` `selectedDeletedFiles`) is still called outside its old file. `lib/core.mjs` shares one `tsc --api` parser per run and awaits its exit on `analyzer.close()`; with `--base`, `lib/crap-inputs.mjs` `filesChangedSince` limits analysis to changed and untracked files (GH-554). `esbuild` is a devDependency for its own build.

- **Sidequest** (`plugins/sidequest`): local orchestration board, typed SQLite store, MCP server, CLI, lifecycle hooks, and dashboard. Core modules are `src/lib/store.ts` (a facade over `src/lib/store/` layers), `db.ts`, `mcp.ts`, `server.ts`, `agentsync.ts`, `context-packet.ts`, `mcp-read.ts`, `mcp-shared.ts`, `prepared-dispatch.ts`, `source-revision-capability.ts`, `worktrees.ts`, `commit-scope.ts`, and `src/bin/`. `src/lib/kernel/` owns pure attempt transitions, submission admission, review binding, assembled-wave delivery decisions (`kernel/wave.ts`), and worktree lease decisions; store and transport modules supply observed facts and persist accepted transitions. `store/submissions.ts` parks immutable candidates, preserves rejected ones, and records integrated replacement evidence. `mcp-review-correction.ts` validates main-only correction requests; `store/review-corrections.ts` records evidenced corrections of an accepted verdict for its exact source candidate. `store/project-watch.ts` gives each watch a project, session, and actor identity so notifications never spill into another board. The `plugins/sidequest/scripts/owned-process-tree.js` and `plugins/sidequest/scripts/owned-phase-supervisor.js` pair owns subprocess groups through timeout and cleanup. `src/lib/hook-timeouts.ts` holds the WorktreeCreate hook budget and setup headroom that `hooks/worktree-create.js` inlines, so worktree setup gives up before Claude Code's hook timeout kills it. `agentsync.ts` renders the stable implementation, diagnostic, and read-only executor definitions from `scripts/_exec-template.md`, including shared-tree preservation and handback guidance. Its `EXECUTOR_CHECKPOINT_TOOL_ROUNDS` constant sets the implementation and read-only checkpoint budget to 75 tool rounds. The common template carries focused checks, final clean-candidate capture, required pre-delivery review and actual shared-resource handoff guidance across profiles; `scripts/generate-bundled-agents.mjs` writes those definitions into the packaged `agents/` directory, while normal SessionStart and CLI sync paths migrate marked legacy generated files instead of recreating them. Since 5.11: `src/lib/store/review-finalization.ts` records an explicit main-thread accept or reject for a bound review that closed via `done` or was never dispatched (`verdict.finalize`, main-attestation authority); `src/lib/worktree-sweep-lock.ts` and `src/hooks/shared/sweep-flight.ts` keep SessionStart and SessionEnd worktree sweeps single-flight with a deadline-owned detached worker; `src/lib/sync-check.ts` backs the `sidequest sync-check` command the executor briefing uses instead of a raw merge-base check. A generated `suite` verify command owns its `cd` (`kernel/verification.ts` `verifyCwdForRequirement`): verify-capture, the integrate gate and the briefing run it from the checkout root, `verifyCwd` applies only to an author-written line, the author's `NAME=value` prefix is kept on every generated step, and add/update warn with both strings before a `suite` verify replaces the recorded line (GH-552, SQ-3709). The executor briefing's `Configured quality gate` line (`agentsync.ts` `configuredQualityGateBody`) reads `.claude/quality-gate/crap.json` before the quartermaster path, defaults the command to `quality-gate.js crap`, and states that legacy bodies whose complexity did not rise never fail (SQ-3720).
- Sidequest lifecycle additions: `src/lib/store/routing.ts` shares `dispatchReadOnly` for explicit cross-provider readonly eligibility. `store.ts` supplies `ticketIntegrationTarget` and `ticketIntegrationTargets` to submission, wave, MCP and CLI delivery paths so recorded per-ticket targets remain authoritative. `src/lib/store/dispatch.ts` reconciles launched-but-never-claimed primary-session dispatches at SessionStart, and its `claimGraceMs` is the single retirement deadline every unclaimed-attempt route (`dispatch`, `groomClose`, `pulse`, `groom-close`) reads. Its crossed worktree binding now parks the displaced sibling's retired creation record on the winner (`crossBoundWorktree.parkedCheckout`) instead of dropping it, and a later claim that adopts the same observed checkout settles that parked record onto the new holder. `src/lib/store/submissions.ts` records typed `done.verify` evidence for commandless working-tree or external-deliverable delivery (`externalDeliverableCloseout`) while command/suite requirements remain capture-bound, and its `applyDeliveryAwaitingContentCommit` keeps an `apply`-mode delivery's `groomClose ... deliveryCommit` binding retryable on verifier failure. `deliveryRevisionPreflight` lets `recordDeliveredSubmission` prove a rebased or squash-merged candidate at a named `deliveryRevision` commit instead of the reachable delivery commit itself, with `resolvedPaths` required for every path the reviewer resolved by hand and refused when the delivery commit is already reachable on its own (PR #146); a reachable-but-merged delivery that isn't a `deliveryRevision` proof still falls back to `git patch-id`-equivalence over the submitted range for a squash merge whose single resulting commit carries no per-candidate-commit patch (SQ-3113). `mcp-lifecycle.ts`'s `inheritedRejectedAdmission` admits a `related`-linked repair's range that inherits an oracle-confirmed rejected candidate. `mcp-shared.ts`'s `resolveLifecycleProject` resolves an omitted-`project` lifecycle call's board from the caller's own claim or worktree binding. `worktrees.ts`'s `retainedWorktreeResumeDecision` refuses to resume a retained checkout stuck mid a cherry-pick, merge, revert, rebase, or bisect, and its WorktreeCreate callbacks are generation-scoped against `stale_attempt`/`missing_attempt`. `agentsync.ts`, `mcp-collaboration.ts`, and `hooks/force-exec-bypass.ts` support reduced Agent schemas by omitting `name` and `mode`; `hooks/bind-runtime-identity.ts` and the store require hook-reported `agent_id` and `permission_mode` `bypassPermissions` before the first claim.
- Sidequest composition admission: `src/lib/mcp-composition-admission.ts` adds main-session-only `update.admitComposition`; `src/lib/store/composition-admission.ts` records and consumes a one-use grant under root/source/review locks, revalidates source and authoritative review generations, and fences dispatch capture/submission/delivery. `src/lib/store/composition-range.ts` proves the complete original `BASE..C` range from pinned source ranges plus scoped root-owned commits. `store.ts`, `store/dispatch.ts`, and `store/submissions.ts` connect admission to fresh isolated dispatch, exact candidate capture/submission, and independent review before delivery; regression coverage is in `test/composition-admission.test.ts`.
- Sidequest board admission and scope: `store/projects.ts` `boardRootRefusal`/`registerProject` refuse an implicit board for a folder inside the Sidequest home, the Claude config directory, system temp (unless the store itself is a throwaway under temp), or a non-git folder; an explicitly named plain folder still registers, and an already-registered board is reused (SQ-3179). `hooks/board-first-reminder.ts` uses the same refusal to stay silent there, and otherwise sends a routed-board reminder or a "no board yet" hint once per session for prompts that look like work requests. `ensureProject` and dispatch (`takeSourceRevisionAdapterSwitch`) migrate a `filesystem-snapshot` board to `git` once the folder becomes a repository, never the reverse, and the dispatch result reports the switch once (GH-334); the snapshot walk in `source-revision-snapshot-child.ts` skips `SNAPSHOT_SKIPPED_NAMES` (`.git`, `node_modules`, build output, `vendor`) and root `.gitignore` rules, and a cap refusal carries bounded skipped/counted samples. `store/dispatch.ts` gives an `allowUnscoped` write dispatch the whole tree (`WHOLE_TREE_SCOPE` `**` in `commit-scope.ts`, recorded as `unscopedOverride.writeScope`) with the board's `alwaysInScope` paths beside it, and refuses that in the shared checkout (GH-341). `store/candidate-refs.ts` moves a board's `refs/sidequest/SQ-n` candidate refs under `refs/sidequest-archived/<board>/` on archive and back on restore, so a new board's SQ-n cannot collide (GH-378).
- Sidequest closeout: `store.ts` `readOnlyChangesOutsideArtifactRoots` lets a read-only `done` pass over paths under its category's `artifactRoots` and refuses anything else in declared scope (GH-332). `store/submissions.ts` `integrationTargetDirt` lets integrate proceed around unstaged or untracked paths the delivery never writes (GH-340, reported as `ignoredDirtyPaths`), while staged or unmerged state still blocks, and a direct claim runs the ticket's current verify rather than a stale dispatch pin, with its own capture invocation (GH-377). `test:files` in `plugins/sidequest/package.json` runs `typecheck` first, so a `tsc` error in a named test file fails a pinned verify (SQ-3204).
- Sidequest evidence executors and isolation (6.1.x): `src/lib/evidence-writes.ts` and `src/hooks/guard-evidence-write.ts` admit an evidence executor's writes only under board-local evidence roots and refuse every repository path, so the packaged `sidequest-exec-dispatch-evidence` and `sidequest-exec-evidence-<effort>` agents (no commit/submit/integrate tools) can write reports without a worktree claim; `src/hooks/shared/shell-writes.ts` treats heredoc and here-string bodies as data, not commands (SQ-3808); `store/dispatch.ts` honours an explicit `sharedTree: false` on a shared-tree board by provisioning an isolated worktree, redispatch inherits it, and the CLI exposes `--no-shared-tree` (SQ-3806); `mcp-lifecycle.ts` `inheritedRejectedAdmission` admits a `related`-linked repair's inherited range from an oracle-rejected candidate, which is how the seven-candidate SQ-3791 chain was delivered as SQ-3839.
- Sidequest routing defaults: `category-defaults.ts` seeds GPT-6.1 Sol (`codex-gpt-6-1-sol`) as the fallback for coding.hard, experiment and spike categories (seed revision 9) and `categoryWithCurrentCodexRoutes` rewrites stored rows still naming the retired Sol/GPT-6 ids, keeping Astra only for frontier categories; `store/routing.ts` `getCategoryRoutePairs` skips disabled categories and keys pairs by `readonly`, so only routed readonly/write pairs get generated executors. The dashboard's `model-windows.ts` shows each backend's window in settings.

- **Model Gateway** (`plugins/model-gateway`): local Claude Code model registry, proxy launcher, readiness/doctor state, schema-4 provider catalog, and ChatGPT/Codex and Grok subscription routing. `lib/process-supervision.js` and `lib/request-worker.js` recover the shared proxy when an active request finds it unavailable; version handling is never-downgrade (`lib/runtime.js` `resolveNewestInstalledCliPath`/`canReplaceInstalledCliPath`): an older CLI's `ensure` leaves a newer serving shim running, and the shim `/restart` refuses an older worker script. State-file writes (catalog, dispatch-route cache, pin cache, Grok auth) go through `lib/atomic-file.js`, which retries replaces that lose to a concurrent reader and sweeps stale `.tmp` siblings, and readiness metadata is written separately from model entries so consumers can explain an unavailable provider without advertising its routes. `lib/runtime.js` `resolveGatewayModelPolicy` is the one per-model window table (backend window, advertised window, `[1m]` picker alias, sentry trigger, now including `gpt-6.1-sol`) that the shim, the compaction sentry in `lib/request-worker.js`, and `doctor` all read. Context windows are one saved setting per backend (`claude`, `codex`, `grok`) in `context-window.json` (`readContextWindowSettings`; defaults Claude `full`, Codex 272000 because OpenAI bills input above 272k at 2x, Grok `full`; legacy `CODEX_GATEWAY_CONTEXT_WINDOW` applies when no valid Codex value is saved), set with `model-gateway.js context-window --claude|--codex|--grok <tokens|full>` (`lib/context-window.js`). Optional saved `compactAt.codex` and `compactAt.grok` values are set with `context-window --codex-compact-at|--grok-compact-at <tokens|cap>`; `cap` removes that provider's override, and cap-only updates preserve it. An explicit positive whole safe token count is bounded by the saved cap and existing provider-derived sentry limit without subtracting `CAP_COMPACTION_MARGIN`; it takes precedence over the reported ignored legacy trigger environment value. Without an explicit value, the synthetic-413 sentry retains cap-minus-85000 policy. Crossing turns and compaction requests can still exceed272k and pay2x. Claude keeps its separate supported native-window setting: a cap is written to project-wired `autoCompactWindow` only where the gateway owns that value, and unsupported direct Claude `compactAt` fields refuse write-free. Settings are startup-read; no role inference, automatic adoption or proven main/subagent split is introduced. The shared context sentry bypasses compaction and separates session, agent and model state. After a synthetic refusal, completed ordinary high-usage responses rearm the next ordinary refusal; low-usage hysteresis remains intact. Codex JSON rearming requires `end_turn`, `stop_sequence`, or `tool_use`, independently of existing transport/readiness success. The shipped Sonnet pin is `claude-sonnet-5-5[1m]` (`claude-sonnet-5[1m]` is in `RETIRED_SHIPPED_PINS`), and `pins.js` resolves saved overrides first. Its `detectedPinOutranksShipped` refuses retired or older detections as defaults, so an older CLI alias cannot replace the shipped Sonnet pin during refresh. `settings-wiring.js` `syncRegisteredProjectPins` rewrites a gateway-owned pin only in projects that already hold that key, so a refresh never newly wires a project. Supervision kills only processes proven to be this install's or a same-marketplace/plugin cache sibling's: ownership probes (`netstat`, PowerShell `Get-CimInstance`, and POSIX `ps -ww`) run asynchronously with a bounded timeout; unknown or foreign owners are left alone, and proxy recovery requires a matching binary plus descendant ownership proof. `lib/windows-detached.js` launches the supervisor through WMI outside the calling hook's process tree and Job Object; `lib/lifecycle-diagnostics.js` keeps bounded lifecycle records in `~/.claude/model-gateway/logs/lifecycle.jsonl` that `doctor` reads to explain an observed exit versus no evidence. Supervisor shutdown waits for pending PID-record writes and supervised children, including fixture shutdown signaling. Ownership probes default to 8 seconds on Windows and 2 seconds elsewhere; exhausted deadlines remain unknown. `lib/codex-upstream-state.js` owns atomic persistent rejection and transient outage evidence. `createRouteTelemetry.finish` in `lib/request-worker.js` makes one terminal readiness decision and canonical `codex_gateway.route` span across retries, after context-error normalization. Completed Codex inference clears both records; transient evidence expires after 60 seconds without reader mutation, while attributed auth rejection takes precedence. Expiry establishes only absence of recent failure evidence; Sidequest's existing catalog refresh can lag five minutes. Compaction handling in `lib/request-worker.js` detects Claude's compaction prompt, retries a buffered Codex stream before exposing output, caps buffering, and records only bounded outcome, upstream status/error, terminal code, and usage counters in route telemetry; `lib/usage-observability.js` keeps the related usage records body-free. A stream that loses its `message_stop` counts as finished only when its own `message_delta` carried an end-of-generation `stop_reason` (`end_turn` or `stop_sequence`), no content followed the stop, and no content block is still open; every other stop reason, `max_tokens` and `tool_use` included, is re-inferred rather than delivered, because a truncated compaction body silently replaces the whole conversation. Lifecycle control is authenticated: `lib/control-auth.js` gates `/restart` and `/drain` on a 0600 token minted before the supervisor listens, and `lib/release-verification.js` checksum-verifies a downloaded proxy before it replaces the installed binary. `lib/shim-state.js` is the one reading of shim state (`running-ours`/`running-foreign`/`starting`/`stopped`) that `commands.js`'s `status`, `doctor`, and `ensure` all import instead of probing separately, so they cannot disagree about whether the shim is up. Reboot recovery (SQ-3791 chain, model-gateway 0.55.0) adds four modules: `lib/lifecycle-lock.js` is one identity-checked lifecycle lock (`lifecycle.lock`, owner pid plus start time, dead owners reclaimed) and the persistent intentional-stop marker `intentionally-stopped.json`, which `stop` writes and only an explicit `start` clears, and only after the supervisor exists with a recorded real PID (`process-supervision.js` `spawnDetached` refuses a spawn without a positive-integer pid); `lib/recovery-policy.js` reads project-local, project and user settings to decide `unwired` (endpoint is not the gateway), `disabled` (an explicit `enabledPlugins` false; an absent entry does not disable) or `recover`; `lib/readiness-gate.js` is the hook body, which recovers on router health only (shim listening on the wired port, `running-ours`, serving version equal to installed, `/healthz` ok) and never on Codex auth or upstream state, printing one actionable guidance line naming the stable launcher on failure; `lib/readiness-hooks.js` installs and removes the gateway-owned `SessionStart` (`startup|resume`) and `UserPromptSubmit` hook groups (`onFailure: block`, 35 s) alongside the wiring. `ensure --quiet` (SessionStart) exits 0 and nudges only when Codex readiness is not `ready`.
- **Live-rules** (`plugins/live-rules`): atomic rule storage and injection into prompts and edits. `hooks/session-start-rules.js` also runs at SubagentStart, keyed per subagent under the parent session, so native subagents get startup-scoped rules once.
- **Release automation** (`scripts/release`): `cut.mjs` plans and prepares or explicitly directly publishes a release, `finalize.mjs` derives tags from manifest changes on the exact merged publish-branch commit, and `guard.mjs` enforces `dev`/`main` invariants plus per-path sync-back waivers. `lib/promotion.mjs` prints promotion and sync PR commands; `lib/publishlock.mjs` wraps the Sidequest publish lock, which serializes participating publishers but cannot provide an atomic remote branch-head compare-and-set.
- **Codebase-mapper** (`plugins/codebase-mapper`): generates atomic project maps, injects the index at session start, and enforces announced map updates through declarative `PreToolUse: Skill` and `Stop` hooks.


Registered plugin packages use a manifest such as `plugins/model-gateway/.claude-plugin/plugin.json`, skill files under `skills/<name>/SKILL.md`, and `hooks/hooks.json`. Hook runtime files are committed JavaScript.

Model Gateway's `lib/tool-schema-compat.js` performs bounded Codex-only schema adaptation after deferred hydration, with local refusal for unsupported affected shapes and unchanged Anthropic bytes. `process-supervision.js` confirms failed proxy health through fresh connections before recovery. Its process-environment diagnostics preserve supported CLI behavior and explain forced Desktop routing limits. Sidequest's cleanup gates cover sweep and failed-creation recovery using recorded dependency-link provenance; explicit read-only base selection is honored. Native Sidequest and Quartermaster guidance gives the orchestrator ownership of the improvement decision and keeps read-only review/audit/debt reports native to Sidequest.

## Shared support

`plugins/test-support/windows-hide.js` scans plugin JavaScript for child-process calls missing `windowsHide: true`. Quartermaster, Observability, and Model Gateway consume it in their tests.

## Dashboard modules

The dashboard has a project rail, toolbar, board views, archive, ticket/settings/notification surfaces, a guided tour (`app/src/lib/components/tour/TourOverlay.svelte`, `app/src/lib/tour/steps.ts`, `app/src/lib/state/tour.svelte.ts`), and a polling state layer. It communicates with the local server through `app/src/lib/api.ts`; it does not access SQLite directly.

- Sidequest guards: `plugins/sidequest/hooks/guards/` is one hooks module that owns PreToolUse registration and the text, context, Git, admission, snapshot, and heredoc guards; `guard-worktree-isolation`, `bind-runtime-identity` and `quota-fallback` stay command hooks because they write to the store. Store modules persist dispatch snapshots and ticket external references.
- Observability (): Claude Code hooks append opted-in per-project JSONL usage records under the Claude config directory;  generates a self-contained board.
- Quartermaster (): setup, resupply, transcript mining, updater, and health checks. Scoring delegates to Quality Gate; no local scorer or CI checker remains.
