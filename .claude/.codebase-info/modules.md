# Modules and plugin catalog

Last Updated: 2026-09-13

## Plugins

- **Sidequest** (`plugins/sidequest`): local orchestration board, typed SQLite store, MCP server, CLI, lifecycle hooks, and dashboard. Core modules are `src/lib/store.ts` (a facade over `src/lib/store/` layers), `db.ts`, `mcp.ts`, `server.ts`, `agentsync.ts`, `context-packet.ts`, `mcp-read.ts`, `mcp-shared.ts`, `prepared-dispatch.ts`, `source-revision-capability.ts`, `worktrees.ts`, `commit-scope.ts`, and `src/bin/`. `src/lib/kernel/` owns pure attempt transitions, submission admission, review binding, assembled-wave delivery decisions (`kernel/wave.ts`), and worktree lease decisions; store and transport modules supply observed facts and persist accepted transitions. `store/submissions.ts` parks immutable candidates, preserves rejected ones, and records integrated replacement evidence. `store/project-watch.ts` gives each watch a project, session, and actor identity so notifications never spill into another board. The `plugins/sidequest/scripts/owned-process-tree.js` and `plugins/sidequest/scripts/owned-phase-supervisor.js` pair owns subprocess groups through timeout and cleanup. `src/lib/hook-timeouts.ts` holds the WorktreeCreate hook budget and setup headroom that `hooks/worktree-create.js` inlines, so worktree setup gives up before Claude Code's hook timeout kills it. `agentsync.ts` renders the stable implementation, diagnostic, and read-only executor definitions from `scripts/_exec-template.md`, including shared-tree preservation and handback guidance; `scripts/generate-bundled-agents.mjs` writes those definitions into the packaged `agents/` directory, while normal SessionStart and CLI sync paths migrate marked legacy generated files instead of recreating them.
- Sidequest lifecycle additions: `src/lib/store/routing.ts` shares `dispatchReadOnly` for explicit cross-provider readonly eligibility. `store.ts` supplies `ticketIntegrationTarget` and `ticketIntegrationTargets` to submission, wave, MCP and CLI delivery paths so recorded per-ticket targets remain authoritative. `src/lib/store/dispatch.ts` reconciles launched-but-never-claimed primary-session dispatches at SessionStart; `src/lib/store/submissions.ts` records typed `done.verify` evidence for commandless working-tree delivery while command/suite requirements remain capture-bound. `agentsync.ts`, `mcp-collaboration.ts`, and `hooks/force-exec-bypass.ts` support reduced Agent schemas by omitting `name` and `mode`; `hooks/bind-runtime-identity.ts` and the store require hook-reported `agent_id` and `permission_mode` `bypassPermissions` before the first claim.

- **Observability** (`plugins/observability`): metadata-only lifecycle telemetry. `hooks/observability.js` observes eight lifecycle events, `lib/observability/` holds the schema, store, ingest, outbox, OTLP sender, and ensure worker, `bin/` holds the observer, statusline, setup, and reports, and `observability/sinks/` selects grafana, otlp, posthog, or none. Setup provisions dashboards from the opted-in project registry and treats dashboard mounts as container freshness. Observer launch is never-downgrade like Model Gateway's: `ensure.js` resolves the newest installed plugin version's `bin/observer.js` from the plugin cache and an older session's ensure leaves a newer live observer untouched (after a stale session kept resurrecting pre-fix observer code). Its adapters read Model Gateway and Sidequest. `observability/sinks/grafana/model-prices.js` applies per-request Astra short/long pricing and `dashboard-generator.js` adds unpriced model token usage without treating it as USD. Split out of Workbench; the `workbench-observer` service name and `workbench_` attribute prefix stayed, because shipped Grafana queries and existing data depend on them.
- **Model Gateway** (`plugins/model-gateway`): local Claude Code model registry, proxy launcher, readiness/doctor state, schema-4 provider catalog, and ChatGPT/Codex and Grok subscription routing. `lib/process-supervision.js` and `lib/request-worker.js` recover the shared proxy when an active request finds it unavailable; version handling is never-downgrade (`lib/runtime.js` `resolveNewestInstalledCliPath`/`canReplaceInstalledCliPath`): an older CLI's `ensure` leaves a newer serving shim running, and the shim `/restart` refuses an older worker script. State-file writes (catalog, dispatch-route cache, pin cache, Grok auth) go through `lib/atomic-file.js`, which retries replaces that lose to a concurrent reader and sweeps stale `.tmp` siblings, and readiness metadata is written separately from model entries so consumers can explain an unavailable provider without advertising its routes. `lib/runtime.js` `resolveGatewayModelPolicy` is the one per-model window table (backend window, advertised window, `[1m]` picker alias, sentry trigger) that the shim, the compaction sentry in `lib/request-worker.js`, and `doctor` all read. Supervision kills only processes proven to be this install's or a same-marketplace/plugin cache sibling's: ownership probes (`netstat`, PowerShell `Get-CimInstance`, and POSIX `ps -ww`) run asynchronously with a bounded timeout; unknown or foreign owners are left alone, and proxy recovery requires a matching binary plus descendant ownership proof. `lib/windows-detached.js` launches the supervisor through WMI outside the calling hook's process tree and Job Object; `lib/lifecycle-diagnostics.js` keeps bounded lifecycle records in `~/.claude/model-gateway/logs/lifecycle.jsonl` that `doctor` reads to explain an observed exit versus no evidence. Supervisor shutdown waits for pending PID-record writes and supervised children, including fixture shutdown signaling. Ownership probes default to 8 seconds on Windows and 2 seconds elsewhere; exhausted deadlines remain unknown. `lib/codex-upstream-state.js` owns atomic persistent rejection and transient outage evidence. `createRouteTelemetry.finish` in `lib/request-worker.js` makes one terminal readiness decision and canonical `codex_gateway.route` span across retries, after context-error normalization. Completed Codex inference clears both records; transient evidence expires after 60 seconds without reader mutation, while attributed auth rejection takes precedence. Expiry establishes only absence of recent failure evidence; Sidequest's existing catalog refresh can lag five minutes. Compaction handling in `lib/request-worker.js` detects Claude's compaction prompt, retries a buffered Codex stream before exposing output, caps buffering, and records only bounded outcome, upstream status/error, terminal code, and usage counters in route telemetry; `lib/usage-observability.js` keeps the related usage records body-free.
- **Live-rules** (`plugins/live-rules`): atomic rule storage and injection into prompts and edits. `hooks/session-start-rules.js` also runs at SubagentStart, keyed per subagent under the parent session, so native subagents get startup-scoped rules once.
- **Release automation** (`scripts/release`): `cut.mjs` plans and prepares or explicitly directly publishes a release, `finalize.mjs` derives tags from manifest changes on the exact merged publish-branch commit, and `guard.mjs` enforces `dev`/`main` invariants plus per-path sync-back waivers. `lib/promotion.mjs` prints promotion and sync PR commands; `lib/publishlock.mjs` wraps the Sidequest publish lock, which serializes participating publishers but cannot provide an atomic remote branch-head compare-and-set.
- **Codebase-mapper** (`plugins/codebase-mapper`): generates atomic project maps, injects the index at session start, and enforces announced map updates through declarative `PreToolUse: Skill` and `Stop` hooks.
- **Quartermaster** (`plugins/quartermaster`): workspace setup and capability passes grounded in session history. Ships the `setup` and `resupply` skills. The miner streams recent transcripts into a bounded signal aggregate: what each session was for (title, opening ask, any `/goal` and whether it was met, a `humanDriven` flag, the areas of the tree touched) plus attribution, habits, and friction (denials, interrupts, corrections). `lib/scan.js` resolves the window, `lib/stream.js` streams records into `lib/signals.js`, which preserves raw host denial kinds and adds `friction.denials.meaning`: `permission-rule` can represent a hook policy block and cannot establish permission-rule provenance or justify allowlisting by itself. `lib/catalog.js` reads local plugin catalogs for recommendations, and `lib/state.js` keeps per-session tallies and the decision ledger that `verify` checks recommendations against. `bin/quartermaster.js` exposes `mine`, `status`, `catalog`, `decisions`, `verify`, `mark-resupply`, and `decline-resupply` (a decline resets the accumulation window so offers stay quiet until evidence re-accumulates). Besides the SessionStart nudge, `hooks/stop-resupply-offer.js` is a Stop hook that blocks the turn once per session when a resupply is overdue, forcing the offer at a real pause; it keeps its own `QUARTERMASTER_OFFER_HOURS` cooldown separate from the nudge's `lastNudgeAt`. It also carries the project bootstrap, Toolshed update, and health-check role that Workbench held until that plugin was folded into it: the `setup`, `update-toolshed`, and `toolshed-doctor` skills, `lib/project-settings.js` as the workspace settings writer (agent teams, compaction window, Sidequest compaction policy), and `bin/update-toolshed.js`, which hands Model Gateway updates to the stable `~/.claude/model-gateway/update.js` launcher installed from the newest active registry entry. That updater records nothing itself and resolves Observability from the install registry rather than importing it, so it works standalone. `lib/gateway-health.js` parses Model Gateway `doctor` output for the SessionStart freshness hook and the doctor skill. `hooks/stop-update-check.js` refreshes stale marketplace data at Stop and reports remote updates or newer installed code without installing or blocking. `lib/project-settings.js` reports the effective `autoCompactWindow`; setup offers 325000 when unset, while doctor reports it read-only. Setup also seeds an adapted reuse-first implementation baseline and self-improvement live rule into each approved workspace.


The six registered plugin packages use a manifest such as `plugins/model-gateway/.claude-plugin/plugin.json`, skill files under `skills/<name>/SKILL.md`, and `hooks/hooks.json`. Hook runtime files are committed JavaScript.

Model Gateway's `lib/tool-schema-compat.js` performs bounded Codex-only schema adaptation after deferred hydration, with local refusal for unsupported affected shapes and unchanged Anthropic bytes. `process-supervision.js` confirms failed proxy health through fresh connections before recovery. Its process-environment diagnostics preserve supported CLI behavior and explain forced Desktop routing limits. Sidequest's cleanup gates cover sweep and failed-creation recovery using recorded dependency-link provenance; explicit read-only base selection is honored. Native Sidequest and Quartermaster guidance gives the orchestrator ownership of the improvement decision and keeps read-only review/audit/debt reports native to Sidequest.

## Shared support

`plugins/test-support/windows-hide.js` scans plugin JavaScript for child-process calls missing `windowsHide: true`. Quartermaster, Observability, and Model Gateway consume it in their tests.

## Dashboard modules

The dashboard has a project rail, toolbar, board views, archive, ticket/settings/notification surfaces, a guided tour (`app/src/lib/components/tour/TourOverlay.svelte`, `app/src/lib/tour/steps.ts`, `app/src/lib/state/tour.svelte.ts`), and a polling state layer. It communicates with the local server through `app/src/lib/api.ts`; it does not access SQLite directly.
