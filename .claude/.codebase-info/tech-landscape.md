# Tech landscape

Last Updated: 2026-08-10

- Node.js is the common runtime. Sidequest uses TypeScript, esbuild, SQLite, and Node's test runner; its build is in `plugins/sidequest/scripts/build.mjs`, and release suite resolution is shared with `scripts/release/lib/suites.mjs` through `plugins/sidequest/lib/suite-resolver.js`.
- Codegraph is a separate CommonJS MCP package using strict TypeScript, esbuild, Node 22.5+, Node's built-in SQLite, and pluggable TypeScript/JavaScript and Python semantic providers. The TypeScript runtime is staged under `plugins/codegraph/runtime/`; the Pyright engine is described by the tracked manifest, lockfile, and integrity metadata under `plugins/codegraph/runtime-pyright/`, with no checked-in install. Codegraph remains under heavy construction and isn't recommended for installation yet.
- The Sidequest dashboard uses Svelte 5, TypeScript, Vite 7, Tailwind's Vite plugin, Vitest, and Playwright. Source is `plugins/sidequest/dashboard/app`; production output is `plugins/sidequest/dashboard/dist`.
- Workbench, Observability, Model Gateway, live-rules, and codebase-mapper ship JavaScript hooks and skills. Workbench also ships a JSON-RPC MCP server that drives native TypeScript 7 or a TypeScript 5 `typescript-language-server` fallback, discards unsolicited TS7 diagnostics, and isolates language-server state by canonical project root. Hook registrations are in each `hooks/hooks.json`; Codebase-mapper uses declarative `PreToolUse: Skill` and `Stop` hooks. Model Gateway also maintains local updater/serving-version state and supports ephemeral shim ports. Codegraph registers a SessionStart JavaScript hook and an MCP server.
- The docs site uses Astro 7 and Starlight. Configuration is `docs/astro.config.mjs`; reference pages are generated by `docs/scripts/generate-reference.mjs`.
- The Windows Sandbox harness is PowerShell under `sandbox/windows/` (gitignored, maintainer-only, no public docs page); its contract test is `sandbox/windows/Test-ToolshedSandbox.ps1`.
- CI uses GitHub Actions. `.github/workflows/test.yml` runs release and plugin suites; release guard and release cut are separate workflows.
- There is no repository database service or Docker setup. Sidequest's local SQLite store is runtime state, not infrastructure.
