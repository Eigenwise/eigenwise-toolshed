# Entry points

Last Updated: 2026-10-17

## User and runtime entry points

- Quality Gate CLI: `plugins/quality-gate/bin/quality-gate.js` exposes project `crap` (configuration, LCOV completeness, same-byte source proof and local receipts) and existing V8 `measure`. Repeatable `measure --new-external-file <absolute path>` explicitly admits new regular `.js`/`.cjs`/`.mjs` files outside the project; external-only calls need neither Git nor a base, while repository or mixed calls require `--base`. External declarations use normalized canonical realpaths, strict UTF-8 raw-byte hashes and an empty per-body baseline; aliases, duplicates, traversal and BOM parser-offset drift are refused. Native V8 capture starts with `QUALITY_GATE_V8_CAPTURE=<empty directory>` and `node --import <file URL of plugins/quality-gate/lib/core.mjs> <test arguments>`; the repository runner passes that preload through `NODE_OPTIONS`. Measurement consumes the same-session executed bytes and exact body/map correspondence; raw V8 reports remain unverified. Native compiler block ends try the exact last-byte mapping first, then an exact exclusive-end closing-token segment with matching bytes; absent or ambiguous correspondence remains unverified. `--project` selects the measured checkout independently of cwd. Python adapter protocol: isolated `lib/python/crap_adapter.py` reads JSON `{text, file, policy?, oracles?}` on stdin and returns `adapterVersion` and independently owned AST rows; this entry measures complexity and inventories executable lines by compiling exact Python source with optimize=0; the LCOV owner joins that inventory to authentic same-byte coverage. Every independently owned executable line needs a DA record; missing, excluded or ambiguous records remain unverified. Other LCOV adapters lack an independent completeness inventory and remain unverified; supported JS/TS uses native V8 measure. Configuration prefers `.claude/quality-gate/crap.json`, with the legacy Quartermaster path as a migration fallback. Missing usable coverage is unverified. Physical source fingerprints select every new or modified independently owned body, including formatting/comment edits; equal/lowered-complexity edits remain enforced and untouched legacy stays outside admission. Python excludes independent child spans in source order, including unordered class decorators and dictionary lambdas. Existing project opt-in and defaults stay intact. The policy enum is `lib/python/policies.json`: default `python-ast-1` and explicit `python-radon-6.0.1-oracle-1`. `--python-policy` overrides config `pythonPolicy`; native-policy config `pythonOracles` supplies exact `{file, name, reason}` selectors. Absent selectors use source-name qualification, `[]` selects none, and a supplied collection is authoritative. Rows expose `measurementPolicy`, `oracleReason` and `oracleSelector`; reports/receipts retain the selected policy and supplied collection. Qualification supplies no runtime collection or coverage proof.

- Sidequest CLI: `plugins/sidequest/bin/sidequest.js`; `dashboard` starts or reuses the local server. Ticket CRUD, stories, comments, links, reminders, archive, and the publish lock are exposed through this CLI. `models sync-agents` now migrates marked legacy generated executor files rather than provisioning a user-level roster. `done --verify` records typed evidence for a commandless working-tree or external-deliverable requirement; command and suite requirements still use the dispatched verify-capture wrapper, which now refuses to run at all over a dirty worktree rather than only refusing to record it. `groomClose --delivery-commit` completes an `apply`-mode delivery by binding its committed working tree, retryable on verifier failure. Delivery paths also trigger worktree cleanup. `worktrees sweep` reconciles retained parked registrations before safe metadata pruning, including on passes with no removals; its help documents rename-first quarantine, age retention and bounded branch-tip compare-and-delete. `sync-check` prints one `ok` or `FAILED <reason>` line for the worktree's merge-base check; `groom-close --worktree <path>` gates a recorded manual delivery in another worktree of the same repository at the target tip; `add --depends-on` links dependencies in the same call.
- Sidequest MCP: `plugins/sidequest/.mcp.json` launches `plugins/sidequest/bin/sidequest-mcp.js`; its read and mutation tools share the store with the CLI. Tool modules are `mcp-read`, `mcp-tickets`, `mcp-lifecycle`, `mcp-collaboration`, `mcp-routing`, and `mcp-review-correction`; the last validates main-only `verdict.correct` requests against the original accepted verdict and exact source candidate; `context_page` continues bounded, revision-bound projections. Lifecycle tools prepare and claim attempts, admit immutable Git or source-revision submissions, record independent verdict/rework decisions, integrate accepted candidates, and supersede rejected predecessors only with delivered repair evidence, including a `related`-linked repair's admitted inherited range from an oracle-confirmed rejected candidate. A lifecycle call that omits `project` resolves its board from the caller's own claim or worktree binding instead of the spawning session's checkout, when more than one board is registered; an ambiguous multi-board match refuses and names them. The update tool also accepts main-session-only `admitComposition` through `src/lib/mcp-composition-admission.ts`; it adopts exact C for a released root and is separate from ordinary field updates. Its bounded expected snapshot is a write-free compare-and-set probe, and dispatch/capture/submission continue through the ordinary lifecycle tools with fresh-generation and independent-review checks. The server exits on stdin EOF, and also when an initialized client stops answering: after a minute of client silence it sends a JSON-RPC `ping` and shuts down if no reply arrives, which reclaims sessions a host abandoned without closing the pipe. Any client message resets that timer, so an actively used server never pings. Reduced Agent-schema dispatch omits `name` and `mode`, and the first claim requires hook-reported `agent_id` plus `permission_mode` `bypassPermissions`.
- Sidequest bundled agents: `plugins/sidequest/agents/*.md` are the packaged stable diagnostic, dispatch, and effort/read-only executor definitions. `plugins/sidequest/scripts/generate-bundled-agents.mjs` regenerates them from `lib/agentsync.js` during the package build, using the common template's focused verification flow and 75-tool-round checkpoint budget from `src/lib/agentsync.ts`; `plugins/sidequest/src/hooks/sweep-worktrees.ts` migrates marked legacy generated files during session-start maintenance. Discovered non-shim providers get generated, marked `sidequest-exec-model-<slug>-<effort>` definitions in the user agents folder instead (`syncDiscoveredModelAgents` in `src/lib/agentsync.ts`), and `src/hooks/force-exec-bypass.ts` strips any Agent `model` passed for them.
- Sidequest hooks: `plugins/sidequest/hooks/hooks.json`; source hooks are under `plugins/sidequest/src/hooks/`. Registered events are WorktreeCreate, UserPromptSubmit, PreToolUse, PostToolUseFailure, Stop, PreCompact, PostCompact, SessionStart, SessionEnd, SubagentStart, and SubagentStop. WorktreeCreate binds the checkout instance and dispatch baseline, falling back to the session's own reserved dispatch repository when the spawning checkout cannot bind; write and shell guards enforce the resulting lease. Its per-checkout callbacks (completed creation, finished provisioning, provisioning failure, dependency link, recovery) carry the dispatch attempt's own generation and refuse a retired or missing generation instead of stamping a replacement attempt. `src/hooks/guard-denied-tools.ts` is a PreToolUse hook that refuses a tool call the claimed ticket's board, category, or read-only-only `deniedTools` setting denies, naming the pattern and telling the executor to comment and release rather than route around it. Subagent hooks bind and retire lifecycle owners, while Stop/compaction hooks emit bounded recovery guidance. `src/hooks/agent-dispatch-state.ts` is a SubagentStop hook that records each ending dispatch's ref, outcome, and terminal time into its worktree's own `.git` directory, for a reaper outside the board to find and stop anything the executor left running there. SessionStart reconciles primary-session dispatches that launched but never bound an agent or claim, then migrates marked legacy generated executor files before sweeping claims and worktrees. SessionEnd calls `sidequest reconcile` on the id it is handed, which forgets that session's claim registrations and reports which claims it left held without releasing any: its payload carries no generation, nonce or owning pid, two of its own reasons fire while the process keeps running, and the event is replayable against a live claim. Those tickets recover through the age backstops instead. TeammateIdle has no registered hook, which prevents board-wide idle wakeups. `src/hooks/force-exec-bypass.ts`, the PreToolUse guard on raw `Agent` dispatch, now reads `src/lib/board-mcp-liveness.ts`'s pid-keyed marker to tell a blocked dispatch attempt whether the Board MCP server it needs has actually exited, never registered, or is unreadable, and points it at `/mcp` reconnect instead of a CLI fallback either way.
- Dashboard app: `plugins/sidequest/dashboard/app/src/main.ts`; shell is `App.svelte`; API client is `app/src/lib/api.ts`.
- Model Gateway CLI: `plugins/model-gateway/bin/model-gateway.js`; dispatches setup/login/start/stop/ensure/status/models/catalog/pin/context-window/env/doctor/remote-control commands. `context-window` keeps separate backend caps and optional Codex/Grok direct maxima (`--codex-compact-at`/`--grok-compact-at <tokens|cap>`); removing an override restores legacy policy, and report/catalog/doctor expose the effective trigger and crossing-turn billing risk. Claude retains supported native-window configuration, with no unsupported direct Claude trigger or inferred role split. Startup, recovery, restart, and drain use bounded ownership probes and leave unknown or foreign listeners untouched; POSIX probes use `ps -ww` so full process commands remain available for install-root checks. `plugins/model-gateway/lib/request-worker.js` recognizes Claude compaction requests, retries buffered Codex streams, and sends metadata-only compaction route diagnostics. Its shared context sentry separates session/agent/model state, bypasses compaction, and rearms after completed ordinary high-usage responses. Codex JSON sentry rearming accepts only `end_turn`, `stop_sequence`, or `tool_use`; incomplete/unknown reasons remain latched. Transport success, readiness and telemetry completion retain their separate semantics.
- Model Gateway lifecycle control: `/restart` and `/drain` on the shim in `plugins/model-gateway/lib/commands.js` are authenticated by `lib/control-auth.js`. A supervisor mints a 64-hex token into `<gateway state>/control-token` at mode 0600 before it listens, and a request must be a POST carrying that token in `x-model-gateway-control-token` (compared with `timingSafeEqual`), a `127.0.0.1:<known port>` Host, `application/json`, and no `Origin` header, and must not arrive on the RC-compatibility listener. A forwarded request therefore has to carry the worker's own Host rather than the client's. `lib/release-verification.js` checksum-verifies a downloaded proxy binary before it replaces the installed one.
- Model Gateway RC control: `POST /internal/rc-compatibility` in `plugins/model-gateway/lib/commands.js` is restricted to the main loopback listener and expected supervisor PID. It probes bindability and reconciles the compatibility listener in that serving process; `lib/remote-control.js` uses it for preflight, activation and conditional hosts rollback.
- Model Gateway hook and skills: `plugins/model-gateway/hooks/hooks.json`, `plugins/model-gateway/hooks/registry-writer.js`, and `plugins/model-gateway/skills/{model-gateway,remote-control-compatibility}/SKILL.md`. Registry writing installs `~/.claude/model-gateway/model-gateway.js`, a version-independent launcher that forwards its arguments to the installed CLI, and `~/.claude/model-gateway/update.js`, which now delegates to that sibling; the launcher is written first so the updater never points at a missing file. Readiness and refusal messages in `lib/runtime.js` name that stable path rather than a versioned plugin-cache path, so an instruction a user is handed survives the next release. CLI `setup`/`ensure` handle atomic proxy replacement and deferred restart.
- Quartermaster maintenance skills: `update-toolshed` and `toolshed-doctor` under `plugins/quartermaster/skills/`; `bin/update-toolshed.js` and `bin/install-workspace-plugins.js` are the bundled programs, with updates handed to the stable Model Gateway updater. Its `hooks/hooks.json` registers SessionStart freshness and billing-path checks plus a UserPromptSubmit freshness check, and Stop hooks for resupply offers and `hooks/stop-update-check.js`, which refreshes marketplace freshness and reports remote updates or installed-version reloads without installing or blocking. `project-settings.js` exposes the effective Codex compaction-window finding used by setup and doctor. Setup also seeds an adapted reuse-first implementation baseline and self-improvement live rule into each approved workspace. Setup and resupply use `skills/setup/references/host-capabilities.md` before recommending host extensions, distinguishing native, installed, and live capabilities and preserving separate installation approval.
- Observability skill: `enable-project-telemetry` under `plugins/observability/skills/`; its setup provisions dashboards from opted-in projects, and `hooks/hooks.json` registers the eight lifecycle observers, the SessionStart ensure worker, and the `Agent|Task` request-body preflight. Grafana targets live in `observability/sinks/grafana/model-prices.js`; Astra uses per-request input tiers and unpriced models appear as token usage.
- Live-rules skills: `manage-rules` and `add-rule` under `plugins/live-rules/skills/`. Hooks: `session-start-rules.js` at SessionStart and SubagentStart, `inject-prompt-rules.js` at UserPromptSubmit, `inject-edit-rules.js` at PreToolUse for edit tools.
- Codebase-mapper hooks: `plugins/codebase-mapper/hooks/hooks.json` registers `PreToolUse: Skill` and `Stop`, both invoking `hooks/inject-context.js`; the hook enforces that an announced map update invokes `codebase-mapper:update-codebase-map`. Map creation/update: `plugins/codebase-mapper/skills/map-codebase/SKILL.md` and `update-codebase-map/SKILL.md`.
- Quartermaster CLI: `plugins/quartermaster/bin/quartermaster.js` with `mine`, `status`, `catalog`, `decisions`, `verify`, `allowlist`, `enable-auto-allowlist`, `mark-resupply`, `decline-resupply`, and `crap` subcommands (`mark-retro` retired); the `resupply` and `setup` skills drive it and never read a transcript directly. `crap` is retired (SQ-3712): `lib/quality-gate.js` `delegateCrap` runs the installed quality-gate plugin's `crap` with the caller's arguments and exits with its code, or prints the quality-gate install command and exits 2 so no gate reads it as a pass; it scores nothing itself. Its `hooks/hooks.json` registers a SessionEnd tally, a SessionStart hook combining the capability-capture charter with a threshold-gated offer of a focused optimization round, and a Stop hook (`hooks/stop-resupply-offer.js`) that blocks the turn once per session when a resupply is overdue so the offer lands at a real pause; declining via `decline-resupply` resets the accumulation window. The pass runs after current user approval or explicit standing permission, and each change needs approval unless that standing permission covers its class. Sidequest ships the `verify-discipline` skill (guidance, no code), which agentsync pins into every executor.
- Windows Sandbox launcher (maintainer-only, gitignored, no docs page): `sandbox/windows/Start-ToolshedSandbox.ps1`; guest entry is `sandbox/windows/bootstrap/Start-ToolshedSandboxGuest.ps1`; contract test is `sandbox/windows/Test-ToolshedSandbox.ps1`.

## Maintainer entry points

- Sidequest build and tests: `plugins/sidequest/package.json` scripts. `plugins/sidequest/scripts/build.mjs` compiles runtime output and generates bundled agents through `scripts/generate-bundled-agents.mjs`; `build-check.mjs` and `test-full.mjs` run package gates through the owned process boundary in `plugins/sidequest/scripts/owned-process-tree.js`.
- Release workflow: `scripts/release/README.md`, then `scripts/release/cut.mjs --prepare`, the printed promotion PR, and `scripts/release/finalize.mjs --push`; `scripts/release/guard.mjs` is the CI invariant checker and prints the sync-back PR commands.
- Docs build and reference generation: `docs/package.json` and `docs/scripts/generate-reference.mjs`.
