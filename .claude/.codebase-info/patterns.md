# Patterns

Last Updated: 2026-09-19

- Build from source, run committed output: Sidequest TypeScript under `src/` compiles to `lib/`, `bin/`, and bundled hook files, while `scripts/generate-bundled-agents.mjs` renders the committed `agents/` roster from `lib/agentsync.js`. Runtime manifests point at generated files; release suite discovery is shared through `plugins/sidequest/lib/suite-resolver.js` and re-exported by `scripts/release/lib/suites.mjs`.
- Stable executor packaging and migration: the Sidequest plugin owns its generated diagnostic, dispatch, and read-only agent definitions in `agents/`; session-start maintenance and normal CLI sync remove only marked legacy generated files from user agent directories, preserving custom content.
- Bounded context projections: Sidequest freezes dispatch contracts and pages large MCP reads with opaque revision-bound handles; callers continue through `context_page` and rerun mutable reads when a revision is stale.
- One store, multiple transports: Sidequest CLI and MCP handlers call the same store functions. Keep lifecycle behavior in typed kernel reducers and store transitions rather than duplicating it in transports.
- Immutable candidate lifecycle: preparation pins baseline and executor identity; submit atomically records the candidate, terminates the executor, and releases its claim. A confirmed review defect preserves and permanently rejects that candidate. A repair has a fresh identity and supersedes the rejection only after integration. Bound-review outcome guidance names the candidate as the subject: accepted approves it, rejected prevents shipment, and prose cannot override the enum. Finalized acceptance has no second-verdict correction path. Dispatch token replacement is staged inside the locked transaction and the prior token is retired only after COMMIT; a rollback removes just the staged file. A repair explicitly linked `related` to a source whose exact candidate carries an oracle-confirmed rejection is the one exception: it can submit the full range that inherits the rejected candidate's commits (`inheritedRejectedAdmission` in `mcp-lifecycle.ts`), keeping the inherited commits so delivery and per-path supersession still see every byte. An `apply`-mode delivery leaves its materialized tree uncommitted; committing it and binding it with `groomClose ... deliveryCommit` completes the same delivery record, and a verifier failure during that binding leaves the delivered record retryable rather than marking it failed (`applyDeliveryAwaitingContentCommit` in `store/submissions.ts`).
- Bound review records remain protected from deletion: `store/tickets.ts` checks direct, reverse and partial bindings on a fresh locked read, with source-first lock ordering. Completion, archive/restore and force do not permit deleting a bound source or review. Unbound deletion removes attachment files only after the database transaction commits, so rollback preserves the row and bytes. This prevents new orphaned bindings; it does not repair existing ones.
- Fresh dispatch reconciliation: primary SessionStart retires only launched dispatches for the current session that have no bound runtime identity or claim, then reports those refs for redispatch; bound or claimed attempts remain protected.
- One retirement authority for every unclaimed-attempt route: `dispatch --recovery-evidence`, `--retire-only`, `groomClose` with `recoveryEvidence`, `pulse`, and `groom-close` all read the same claim-grace deadline (`claimGraceMs`, `SIDEQUEST_CLAIM_GRACE_MIN`, default 15 minutes, clamped to the idle backstop) measured from an attempt's latest runtime signal: launch, WorktreeCreate start/completion, finished provisioning, bind, briefing fetch, claim, or a trusted same-session board write under the bound runtime name after launch and before any claim. An attempt whose WorktreeCreate never recorded finished provisioning never becomes grace-retirable, because a cold `npm ci` looks identical to a dead hook; it only reaches the longer idle backstop. WorktreeCreate's five per-checkout callbacks (completed creation, finished provisioning, provisioning failure, dependency link, and recovery) are generation-scoped and refuse as `stale_attempt` or `missing_attempt` instead of stamping a replacement attempt that reused the same session and checkout; the start binding itself cannot be generation-scoped because the hook learns its generation from that call, so it stays scoped to the session and checkout instead.
- Adapter-owned facts: Git repositories and non-Git projects resolve immutable candidate existence and baseline membership through registered capabilities. Callers cannot assert those facts, and an unavailable adapter fails closed while preserving the retry candidate.
- Lease every checkout: worktree operations require repository, dispatch baseline, bound path, checkout-instance digest, phase, and liveness facts. Paths, branches, sessions, and process presence are hints rather than cleanup authority. Resuming a retained checkout additionally refuses one with unmerged index entries or an in-progress cherry-pick, merge, revert, rebase, or bisect: a conflict does not move HEAD, so a stuck replay still matches its release-time identity and would otherwise hand the replacement executor a partial candidate (`retainedWorktreeResumeDecision` in `worktrees.ts`). Nothing is auto-resolved; the conflicted checkout is preserved as failed-replay evidence and the replacement executor gets a fresh isolated checkout instead.
- Provider routes come from one capability decision: Sidequest accepts only fresh, valid, ready schema-4 Model Gateway catalogs for routing and model advertisement. Provider metadata may survive for precise refusal messages; stale or unready entries never materialize GPT defaults. Explicit provider-crossing overrides use the existing `dispatchReadOnly` authority, including ticket-level overrides, and are allowed only for effectively readonly work. Writable crossing and automatic cross-provider fallbacks remain refused; later edits cannot change an already-prepared readonly executor, route or review binding. Every dispatch prompt ends with a `[sidequest-route model=... effort=... ticket=SQ-n]` marker; Model Gateway reads the ticket field into its usage rows, so gateway spend is attributable per ticket without parsing transcripts.
- Isolated worktree creation resolves the board from the spawning checkout, falling back to the session's own reserved dispatch repository when that checkout cannot bind, so a cross-project isolated dispatch is still cut from the ticket's own repository; prepare-time refusal now fires only for the genuinely ambiguous case, a session holding launched isolated dispatches on two boards at once, and names both paths and the `sharedTree:true` escape. Tests that dispatch temporary boards run the call from the board's checkout.
- Lifecycle MCP calls that omit `project` resolve the board the same way, from the caller's own binding, when more than one board is registered: the dispatch's own worktree for an isolated dispatch, or the claim owner named by `by` for a shared-tree one (`resolveLifecycleProject`/`boardBindsCaller` in `mcp-shared.ts`). A caller bound to more than one board refuses and names them; a caller bound to none stays on the spawning session's board with its existing refusals unchanged. A call that takes no `worktree` argument (comment, release, done, claim, plan, scope requests) needs `project` to reach a sibling board.
- Integration targets belong to the ticket's recorded dispatch: submit, wave assembly and delivery resolve that target through `ticketIntegrationTarget`, falling back to board configuration only when no target was recorded. `commit-scope.ts` derives qualified local and frozen remote proof refs; range validation carries target mode through submit and queue reads so same-named tags cannot shadow the upstream. Equivalent-patch and content checks use the same matched ref and commit. Missing required remote proof fails closed; an absent optional local branch cannot mask remotely landed work during abandonment. Mixed-target waves refuse; source-revision invalidation returns a structured refusal without assuming a Git branch. Candidate overlap is judged on the candidates' real changed paths, not on intersecting declared scope directories, and a refused integrate names the manual pinned-candidate route (local merge, gate, then `integrate` with `deliveryCommit`). Synthetic delivery tests configure their actual board target and restore prior configuration instead of fabricating caller-supplied target objects.
- Per-request pricing stays close to usage: Observability selects Astra's short or long input tier from each request's input/cache totals, while unpriced resolved models are grouped as token volume and excluded from USD totals.
- Verify produced behavior: ticket oracles observe the required property on output. Implementation-name greps are diagnostics, and overlapping terminal waves rerun the property oracle after assembly. Commandless shared-tree or external-deliverable requirements close with typed `done.verify` evidence, forwarded through `externalDeliverableCloseout`; command and suite requirements stay bound to their matching verify-capture, and review verification is refused for working-tree delivery. verify-capture refuses to even run the pinned command over a dirty worktree, not only to record the capture afterward, except for a working-tree-delivery target identified by the content hash of its own uncommitted paths. Single-ticket wave admission reuses the candidate's submit verify-capture instead of re-running the pinned command, but only when that capture recorded a clean worktree at the candidate's committed content; a capture taken over uncommitted edits, and any capture recorded before that field existed, falls back to provisioning a worktree and running the command. The merged-tree gate at delivery always runs.
- A suite answers for its own checkout: ambient environment is what makes a local run disagree with CI, so `plugins/sidequest/test/_sidequest-test-home.ts` pins `SIDEQUEST_HOME`, the git config vars, and (through `test/_hook-runtime.ts`) `CLAUDE_PLUGIN_ROOT`, which hooks resolve `lib/*.js` under. Without that pin a suite spawned from a plugin-hosted process runs its hooks against the installed plugin while its assertions drive the checkout. `suiteEnvironment()` in `scripts/release/cut.mjs` strips the same variable along with the session and agent identities and every credential before any release or verification suite runs. A test needing a different identity or root sets its own.
- Serialize board mutations: MCP mutation handlers enqueue per-board work before touching state.
- Preserve exact ownership: Sidequest reclaims claims and pre-claim dispatch bindings only after confirmed terminal process evidence, keeps unknown owners protected, and checks ownership before forced submission, release, or rejection-history mutation. Model Gateway applies the same floor to startup, recovery, restart, and drain; bounded unknown or foreign port owners remain untouched, and POSIX `ps -ww` preserves the command text needed for install-root checks. POSIX probes run their child with `LC_ALL=C` so `lstart` parses under any user locale; Windows inherits its environment.
- Owned process phases: `plugins/sidequest/scripts/owned-process-tree.js` starts each gate under a detached supervisor, classifies terminal process and group states, bounds retained output, and delays settlement until cleanup evidence is drained. Unknown or still-live ownership remains blocking.
- Batch-local Stop responsibility: each plugin deduplicates only its own Stop work using stable inputs; mutable transcript metadata and prompt identifiers do not define responsibility, and stale lock cleanup is generation-bound.
- Freshness checks are advisory and version-keyed: Quartermaster refreshes marketplace data at Stop and reports updates or reloads without installing, blocking, or repeating the same version warning. Its mutating updater and migration preflight the Claude executable once before any update mutation; an unavailable executable stops with the existing `--claude` override guidance, while check and dry-run remain nonmutating.
- Atomic gateway updates and request recovery: Model Gateway stages proxy replacements, renames atomically with rollback, compares serving versions, and defers restart when the listener cannot exit immediately. An active request can start or recover the shared proxy without waiting for another Claude SessionStart.
- A refusal names a command the reader can actually run: Model Gateway's readiness and auth messages live once in `plugins/model-gateway/lib/runtime.js`, keyed to the stable `~/.claude/model-gateway/model-gateway.js` launcher, and `commands.js` plus `request-worker.js` import that table instead of composing their own. Codex authentication failures are rewritten on the forward path so the client sees that command instead of the upstream proxy binary that is never on PATH, with the real HTTP status and the upstream detail preserved alongside the instruction. Anthropic passthrough responses are never rewritten, and a 403 is treated as an auth failure only when its body says so.
- Shared-tree artifacts are marker-gated and confined to an approved artifact root. Closeout can exempt disjoint sibling allocations only with matching recorded session, shared checkout and valid overlapping intervals. Completed sibling candidate/content integrity is validated before dirty inventory; missing, restored or committed-away paths cannot evade it. A mismatch refuses with `working_tree_sibling_integrity_violation`. Unallocated drift stays blocked with preserve-and-hand-back guidance, never instructions to revert someone else's work or broaden scope.
- Hook registration is declarative: events and matchers live in `hooks/hooks.json`; source or generated hook code implements behavior. Codebase-mapper blocks an announced map update until the matching Skill invocation is recorded.
- Generated docs are disposable: `docs/scripts/generate-reference.mjs` owns `docs/src/content/docs/reference/`; edit manifests or the generator instead.
- Stream oversized inputs, never load them: quartermaster's miner reads transcripts line by line into bounded collector state and emits aggregates, because one session runs to tens of megabytes. Quotes, titles, and paths are clipped in one place as they are collected, so no reporting path can leak a whole transcript into context.
- Poll local APIs: the dashboard uses HTTP JSON endpoints and a 2.5-second polling layer, with no browser-side SQLite or WebSocket dependency. CI watch failure alerts exclude skipped and neutral conclusions without treating either as successful verification.
- Keep project opt-in local: Quartermaster writes project-local settings, and Observability writes telemetry opt-in state, rather than machine-wide configuration.
- One export authority, and denial outlives the process: repository consent is enforced at Observability's store ingest, and the observer outbox is the only path logs leave the machine by. The Collector keeps trace and metric sink pipelines but has no `logs/sink` pipeline, because a static YAML pipeline cannot follow a mutable consent file. A denial is persisted as a `consent_denial(session_id, denied_at)` tombstone in `plugins/observability/lib/observability/consent.js` and consulted when the session map warms, so an observer restart cannot resurrect a denied mapping; re-opting in clears it. Denied spool rows are retained rather than deleted. Gateway usage rows whose `project_id` is not a hex64 id are treated as a project NAME resolved against the session map and fail closed on mismatch, so a name cannot borrow another session's consent.
- One project identity, hex everywhere it is an id: ingest requires `SAFE_PROJECT_ID` (hex 32-128 or `hmac:`) and rejects the whole observation otherwise, so every emitter sends the repository SHA-256 as the id and the sanitized basename as a separate `project.name` label. `plugins/observability/bin/project-telemetry.js` writes both into `OTEL_RESOURCE_ATTRIBUTES`, matching what the hooks already derive. Because a repository keeps emitting its old value until somebody re-runs the enable command, the Grafana generator (`plugins/observability/observability/sinks/grafana/dashboard-generator.js`) matches `project_id` against the union of each project's id AND name; that name half is transitional and can go once every wired repository has been re-enabled. Loki keeps matching `workbench_attribute_project_name` on the name, which is a different label and not part of this.
- A review needs two proven runtimes, and the two bind sources are not symmetric: `plugins/sidequest/src/lib/kernel/review-binding.ts` compares immutable terminal attempt snapshots and admits a pair only when the candidate and its bound review came from provably different runtime identities. A hook-bound attempt carries a real `agentId`; a `claim_token` attempt never does, only `agentName` plus `tokenPrefix`. Accepting a claim-token attempt as an identity on BOTH sides would let two same-session siblings review each other, so it stands as an identity on one side only. Attempts predating the `bindSource` field fall back to `boundAt`, because refusing them outright deadlocks candidates that were already submitted and reviewed.
- Cap an unbounded scan, do not narrow what it hashes: `plugins/sidequest/src/lib/source-revision-capability.ts` bounds the non-git filesystem snapshot with a path cap, a byte cap and a wall-clock deadline (500 / 64 MiB / 10s), refusing through `FilesystemSnapshotLimitError` and naming the bound, the observed value and the recourse. Adding `node_modules`-style exclusions instead would be the obvious fix and is deliberately not done: the digest is a persisted baseline identity, so changing what gets hashed silently invalidates every stored non-git baseline. The deadline is enforced from outside the process because it has to be: a blocking `readFileSync` (a cloud-sync placeholder hydration) is uninterruptible in-process, and `worker.terminate()` does not stop a worker sitting in a synchronous syscall. So the walk lives in `source-revision-snapshot-child.ts`, run through `spawnSync` with a timeout, and the child names each path on stderr before reading it so the deadline refusal can report the file it died on.
- A protected release is prepared from `develop` by `scripts/release/cut.mjs`, promoted into `main` through a reviewed PR, then finalized by `scripts/release/finalize.mjs` at the exact remote `main` head. Finalize derives moved versions from the merged commit's first parent, tags that explicit sha, and prints the sync-back PR; `scripts/release/guard.mjs` grants sync-back exemptions per release-owned path only when the resulting tree entry has the same blob and mode as the pinned publish commit. The Sidequest publish lock serializes participating publishers but cannot close the unrelated-writer tag-only remote race.
- Compaction diagnostics are metadata-only: `plugins/model-gateway/lib/request-worker.js` identifies Claude compaction requests, buffers and retries a Codex SSE stream before visible output within a byte cap, then records bounded outcome, terminal/error/status, and usage fields in `codex_gateway.route`; summary text, prompts, and raw responses stay out of telemetry.
- A transient commit is proved by its tags, never by its own shape: `unpublishedReleaseTip` in `plugins/sidequest/src/lib/commit-scope.ts` refuses a dispatch baseline sitting on a release commit that is about to be rewound, and it decides that from ANNOTATED tags pointing at the commit (`%(objecttype)` = `tag`, so a lightweight tag never counts) whose set matches a marketplace `v<semver>` plus at least one `<plugin>-v<semver>` BY SHAPE, never by a hard-coded count, combined with non-reachability from `refs/remotes/origin/<integration branch>`. The commit message, author, parent count, reflog and an emptied `.release/unreleased/` were all evaluated and rejected as distinguishers because each is user-controlled or absent. The cut itself tears the window down (`scripts/release/cut.mjs`), so this refusal is normally only visible mid-cut; it earns its keep when that rollback fails. Residual known cost: the reachability half reads a local remote-tracking ref, so a checkout that has not fetched a push made elsewhere can refuse a baseline that is in fact published. It fails safe and names its reason.
- Quartermaster setup seeds an adapted reuse-first implementation baseline and self-improvement live rule; setup and resupply share `skills/setup/references/host-capabilities.md` to distinguish the target host's native support, installed configuration, and live usability. Catalog evidence applies only to the host it inventories. Working delegation closes the gap; an installed but unloaded extension calls for activation and a live check. Official host examples, including Pi's subagent example, can be recommendations without implying Quartermaster runs under that host. Installation and configuration remain separately approved. `skills/resupply/evals/evals.json` holds skill-creator scenarios; prose/schema tests do not establish fresh-context recommendation efficacy.
- Cross-plugin use is registry-resolved, never imported: a plugin cannot `require` across plugin roots, so Quartermaster finds Observability through `~/.claude/plugins/installed_plugins.json` and degrades to a no-op when it is absent. Observability uses the same registry to provision project dashboards, and Model Gateway uses it to resolve its stable updater. Small shared helpers are duplicated per plugin instead.
- Bounded schema compatibility: classify all hydrated Codex tools before mutation; admit only proven positive schema/regex contexts, preserve unrelated schema bytes and refuse unsupported affected shapes locally. Ajv Draft 2020 tests compare accepted inputs and authentic prior-adapter fixtures.
- Improvement decisions stay with the orchestrator: research supplies evidence, executors implement the pinned benefit, approach and boundary. Native read-only review/audit/debt recipes remain available on their own.
- A confirmed blocker within delegated scope gets acted on, not just reported: the `user-story` skill's wave-execution guidance dispatches the existing ticket once it is ready, or starts authorized prerequisite preparation, recording the concrete dependency, owner, and resume condition. Unrelated CI or review is not treated as a dependency, and acknowledging or reprioritizing a report does not count as taking ownership of it.
- Terminal inference owns passive readiness: Model Gateway finishes state and telemetry once after retries and existing context-error normalization. HTTP 200 headers cannot establish success; semantic failures retain auth evidence and their actual HTTP status. Normalized context overflow remains a client error, and transient expiry is nonmutating evidence aging rather than proof of recovery.
- Preserve host data without inventing provenance: Quartermaster retains denial kinds and counts, but its report caveat and skills distinguish a host-reported policy block from a proven permission-rule cause. Tool names and reason prose do not supply missing hook provenance. Bare PowerShell fingerprints are excluded from automatic permission recommendations and rechecked before settings writes; existing user allow and deny rules remain untouched, and no scoped PowerShell rule generation is provided.
- Synthetic wiring tests isolate home, environment and cwd so real project settings cannot shadow fixtures. Unknown and confirmed foreign process fixtures supply distinct evidence rather than sharing a null process result.
- RC capability belongs to the serving supervisor: PID-pinned main-loopback control probes and reconciles its configured listener without restarting the worker. Probes close on successful bind and retain cleanup ownership through closure; unavailable or unknown capability refuses enable before hosts writes. Failed activation restores only unchanged command-written hosts bytes, preserving observed external edits. Bound or bindable results report local HTTP transport only; end-to-end Remote Control is documented as unverified for the inspected client versions.
- RC synchronization checks required health before migration, finishes migration before choosing the writable scope, and reports verified settings readback rather than the requested mode. Already-compatible environment-only wiring remains process-limited and creates no settings; disable remains available without a bindability gate.
- The Windows Sandbox harness (`sandbox/windows/`, gitignored, maintainer-only) maps only its bootstrap directory read-only and tests isolation and feature flags before launch.
