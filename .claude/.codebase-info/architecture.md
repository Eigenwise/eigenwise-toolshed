# Architecture

Last Updated: 2026-09-10

## Repository shape

The repository is a plugin marketplace. Seven plugins are registered in `.claude-plugin/marketplace.json`: `plugins/sidequest`, `plugins/observability`, `plugins/model-gateway`, `plugins/live-rules`, `plugins/codebase-mapper`, `plugins/quartermaster`, and `plugins/whittle`. `plugins/test-support` is shared test support, not a plugin.

## Runtime flow

Claude Code loads runtime files declared by plugin manifests and hook manifests. Sidequest builds TypeScript from `plugins/sidequest/src/` into committed `agents/`, `lib/`, `bin/`, and `hooks/` output. `plugins/sidequest/scripts/build.mjs` runs `scripts/generate-bundled-agents.mjs`, which derives the stable executor markdown roster from `lib/agentsync.js`; runtime manifests point at the generated files. Its MCP entry is `plugins/sidequest/bin/sidequest-mcp.js`, configured by `plugins/sidequest/.mcp.json`; hooks are registered in `plugins/sidequest/hooks/hooks.json`. CLI and MCP handlers share store operations in `plugins/sidequest/src/lib/store.ts`. The typed lifecycle reducers and worktree lease decisions live under `plugins/sidequest/src/lib/kernel/`; transports adapt repository, immutable-revision, process, and checkout facts into that kernel. Release and test phases use `plugins/sidequest/scripts/owned-process-tree.js` with its detached supervisor to retain process ownership through cleanup. Commandless shared-tree delivery can close with typed `done.verify` evidence for document, link, schema, manual, attestation, or custom requirements; command and suite requirements still need a matching verify-capture, and review verification is refused for working-tree delivery.

Sidequest persists board state in SQLite and serializes mutations per board. The orchestration loop covers dispatch, routing, categories, executors, claims, submissions, scope enforcement, and worktree management through typed store and lifecycle modules. Stable executor definitions are loaded from the package's `plugins/sidequest/agents/` roster; session-start maintenance and `models sync-agents` migrate only marked legacy generated files and preserve custom or unreadable agent files. Confirmed terminal process evidence can release the exact dead claim or pre-claim dispatch binding; live and unknown owners remain protected, and ownership is checked before forced submission or release mutations. `plugins/sidequest/src/lib/agentsync.ts` compiles dispatch briefings and ships them whole; a briefing larger than Claude Code's Bash output cap is written to a file under the store home and the executor is told to Read it. `mcp-read.ts` exposes `context_page` for paging list/comments rows, and `mcp-shared.ts` derives every read-result ceiling from Claude Code's 25,000-token MCP result cap via `context-packet.ts` (no self-chosen byte budgets). The dashboard is a separate Svelte/Vite app that talks to the local server over HTTP `/api/*` and polls state.

## Dispatch lifecycle

The dispatch lifecycle freezes the story contract, provider/model identity, source baseline, and briefing snapshot at preparation time; the briefing carries its full text, so `context_page` pages only board reads, never briefing sections. Submission is a terminal executor transition: the store atomically parks the immutable candidate, releases the claim, and prevents that executor from resuming it. Review rejection preserves the candidate and its evidence; repair uses a fresh candidate identity, and only an integrated replacement can supersede the rejected submission. Worktree creation, write, resume, and cleanup each require an immutable lease binding. Cleanup additionally requires terminal liveness, the original checkout-instance marker, and a registered worktree owned by the store. Primary-session start reconciles launched dispatches that never bound an agent or claim, marks them failed, and reports refs for redispatch; bound runtime identity and claim state remain protected.

Quartermaster bootstraps project configuration, updates Toolshed installs through the stable Model Gateway updater launcher, migrates legacy gateway state, and reports effective Codex `autoCompactWindow` settings. Its setup seeds an adapted reuse-first implementation baseline and self-improvement live rule into each approved workspace write list. Its SessionStart and UserPromptSubmit freshness checks are advisory; its Stop update check refreshes marketplace freshness and reports available updates or plugin reloads without installing or blocking. It hands telemetry setup to Observability, which owns the observer, Collector, sinks, and statusline. Model Gateway's `plugins/model-gateway/bin/model-gateway.js` maintains the local proxy, shim, readiness state, catalog, and model routing for `claude-gpt-*` and `claude-grok-*` models, while retaining legacy `claude-codex-gpt-*` compatibility; it can bind an ephemeral shim port, record serving version, and defer restart; supervision enforces a never-downgrade invariant, so a stale session's `ensure` leaves a newer serving shim running, same-marketplace/plugin cache siblings can be replaced, foreign installs stay untouched, spawns resolve the newest installed CLI, and the shim's `/restart` refuses adopting an older worker script. Startup, recovery, restart, and drain use bounded ownership probes; unknown or foreign listeners stay untouched, and POSIX `ps -ww` probes preserve full command lines for ownership checks. Shutdown waits for pending PID-record writes and supervised children, while fixture shutdown can signal the supervisor directly. Observability provisions Grafana dashboards from the local opted-in-project registry. Its model pricing handles Astra's per-request short/long input tiers and keeps unpriced model usage visible as token volume instead of inventing a dollar total. Live-rules injects matching developer rules at prompt and edit time. Codebase-mapper injects `.claude/.codebase-info/INDEX.md` at session start and enforces main-session map updates through PreToolUse and Stop hooks. Quartermaster's miner reads outside the repository: `plugins/quartermaster/lib/scan.js` selects transcripts from `~/.claude/projects/<slug>/`, including per-session `subagents/*.jsonl`, and `lib/signals.js` reduces them to a bounded JSON aggregate on stdout. Its per-session tallies and decision ledger live under `~/.claude/quartermaster-state/`, so nothing is written into the project.

`plugins/whittle/` applies one canonical clean-code policy from `skills/whittle/SKILL.md` through its parameterless `hooks/lib/runtime.js` renderer at Claude session and subagent start. It ships nothing for other hosts: no exports, adapters or MCP server. Mode selection, saved preferences, switching commands and statusline code are removed; plugin enablement controls injection.

Model Gateway's `lib/tool-schema-compat.js` classifies hydrated Codex tool schemas before making bounded positive-context compatibility copies; unsupported affected schemas refuse locally, and Anthropic request bytes remain unchanged. Recovery confirms a failed health probe through a fresh connection before replacing an owned listener. Process-environment diagnostics distinguish user-controlled CLI launches from forced Desktop overrides; signed-in Desktop gateway routing remains unsupported. Sidequest cleanup records exact dependency-link provenance and validates it before sweep or failed-creation recovery; explicit read-only worktree bases are honored while automatic selection stays on the preparing checkout.

`sandbox/windows/` is a maintainer-only, gitignored (`.gitignore`: `/sandbox/`) Windows Sandbox clean-room harness: it generates an isolated `.wsb`, maps only its bootstrap directory read-only, and validates its PowerShell scripts with `Test-ToolshedSandbox.ps1`. It has no public docs page and is never pushed to the shared repository.
